## 2. 综合分算法——发现并修复核心缺陷

### 2.1 现象（修复前）
重新计算并拉取 `GET /api/algorithm/composite-score`：
- 100 个排名中，**仅 1 个学生（user 2）带有 academic_score**，其余 99 个 academic=0。
- 综合分退化：除 user 2 外，所有学生的学术维度均为 0。

### 2.2 根因（关键发现）
`services/composite_score_service.py` 中计算学业特征的 3 处聚合查询（约第 68-78、276-286、403-413 行）使用了：

```python
db.session.query(Score.student_id, func.avg(Score.score).label("avg_score")) \
    .filter(Score.student_id.in_(user_ids), Score.score > 0) \
    .all()                       # ← 缺少 .group_by(Score.student_id)
```

SQLite 中 `SELECT student_id, AVG(score) ... WHERE ...` **不带 GROUP BY** 时，整张表被视为一个分组，只返回 **1 行**：一个任意 `student_id` + **全局平均分**。经实测复现：
- 缺 `group_by`：`rows returned: 1 -> [(2, 75.66)]`（user 2，全局均值 75.66）
- 加 `group_by(Score.student_id)`：`rows returned: 100`（每个学生独立均值）

这不是 WAL 快照/连接陈旧问题（全新进程、新连接也复现），而是**纯粹的 SQL 聚合缺陷**。三处 `unlock_counts` 查询（含 `group_by(ScoreRecord.user_id)`）写法正确，唯独三处学业均值缺失分组。

### 2.3 修复
三处学业均值查询均补上 `.group_by(Score.student_id)`，重启后端（进程 PID 1684，项目 `.venv`）后重新计算。

### 2.4 修复前后对照

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 带 academic>0 的学生数 | **1 / 100** | **100 / 100** |
| 综合分最小值 | — | 0.3 |
| 综合分最大值 | — | 99.5 |
| 综合分均值 | — | 38.0 |
| 综合分标准差 | — | 40.5 |
| NaN 数量 | 0 | **0** |
| 熵权权重（behavior / academic / compliance） | 0.16 / 0.84 / ≈0（受 99 个 0 的偏态假象拉高 academic 权） | 0.92 / 0.08 / ≈0（真实分布下 academic 更均匀→权降低） |

> 说明：修复后 academic 权重大幅下降，是熵权法对**真实数据分布**的正常反应——此前 0.84 的高权重恰是“99 个 0”造成的偏态假象。修复使每个学生的 academic_score 为其真实平均成绩，正确性已确认。权重高低属于建模取舍：若希望考试成绩对综合分有更大影响，可改用等权或固定权重方案（非本轮缺陷）。

## 3. 预测 / 风险算法抽样核对

### 3.1 `/api/algorithm/prediction/risk`（PredictionService，基于 `score_record` 时序）
- 修复前（无行为数据）：返回空列表。
- 导入行为时序后：返回 **25 名学生**（即 seed 中 critical 陡降画像组，线性斜率 < 阈值 -5，被判定为“下降风险”）。端点运行正常、结果可解释。

### 3.2 `/api/algorithm/risk-predict/high-risk` 与 `/risk-predict/batch`（RiskPredictService）
- `batch` 返回 **101** 条结构化结果，风险级别分布：**medium = 52，low = 49，high = 0**。
- 综合风险分 `overall_score = 0.4·academic + 0.35·behavior + 0.25·attendance`；“high”需 `overall_score ≥ 0.7`。
- 抽样（top）：胡浩 `score=0.67`（behavior 0.75 / academic 0.90 / attendance 0.20）、周秀 `0.57`、王杰 `0.57`。
- **为什么没有“high”**：本轮仅导入了**行为时序**，缺失**出勤（attendance）**与**成绩下滑趋势（academic trend）**两个维度。attendance 风险分恒为 0.20（贡献上限 0.05），即便 behavior+academic 较高也只能到 medium。这属于**数据完整性**问题，不是代码缺陷——端点逻辑、分级、干预建议均正常输出。

## 4. 结论

1. **综合分算法：发现并修复 1 个核心缺陷**（缺失 `GROUP BY` 导致学业维度仅 1 名学生有值、其余退化为 0）。修复后 100/100 学生获得真实学术分，综合分分布合理（0.3–99.5，0 NaN）。这是本轮最关键的可交付成果。
2. **预测/风险算法：在补入行为时序数据后均正常产出**，结果可解释、无崩溃、无 NaN。
3. **风险“high”层级暂未触发**：受限于未导入出勤与成绩下滑趋势数据，属数据完整性范畴，建议后续补充这两类数据以完整验证 high-risk 判定路径。
