## 三、第一阶段实施计划

### 3.1 数据库索引优化

**目标**：为用户查询的关键字段添加索引，提升搜索性能

**实施步骤**：
1. 在 `User` 模型中为 `name`, `card_id`, `phone`, `class_name` 添加索引
2. 创建索引迁移脚本
3. 执行数据库迁移

**文件修改**：
- `backend/models/__init__.py` - 添加索引定义
- `backend/scripts/create_indexes.py` - 索引创建脚本

### 3.2 API响应压缩

**目标**：启用 gzip/brotli 压缩，减小响应体积

**实施步骤**：
1. 在 Flask 应用中添加压缩中间件
2. 配置压缩级别和支持的编码格式

**文件修改**：
- `backend/app.py` - 添加 flask-compress 配置

### 3.3 创建聚合仪表板API

**目标**：提供单一端点返回仪表板所需的所有数据

**实施步骤**：
1. 创建 `/api/dashboard` 端点
2. 聚合用户统计、设备状态、通知等数据
3. 添加缓存策略

**文件修改**：
- `backend/api/dashboard_routes.py` - 新文件

## 四、第二阶段实施计划

### 4.1 前端集成聚合API

**目标**：修改 Dashboard 页面使用聚合 API

**实施步骤**：
1. 修改 `Dashboard.tsx` 的数据获取逻辑
2. 更新 API 服务层
3. 测试数据展示正确性

**文件修改**：
- `frontend/src/pages/Dashboard.tsx`
- `frontend/src/services/api.ts`

### 4.2 WebSocket重连策略

**目标**：实现指数退避重连，提高连接稳定性

**实施步骤**：
1. 修改 WebSocket store 的重连逻辑
2. 添加指数退避延迟计算
3. 添加最大重连次数限制

**文件修改**：
- `frontend/src/stores/index.ts`

### 4.3 ETag条件请求支持

**目标**：添加 If-None-Match 请求头支持

**实施步骤**：
1. 后端返回 ETag 响应头
2. 前端缓存并复用 ETag
3. 条件请求时携带 If-None-Match

**文件修改**：
- `backend/utils/cache_middleware.py`
- `frontend/src/services/api.ts`
