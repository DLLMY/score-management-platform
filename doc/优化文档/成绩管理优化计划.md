# 成绩管理模块优化计划

## 文档概述

本文档记录了成绩管理模块（积分记录、规则管理、审批流程、排名系统、综合评分）的专项优化计划，包含优化项清单、优先级排序、实施步骤、验证标准及进度追踪表格。

---

## 三、第一阶段实施计划（功能补全）

### 3.1 审批拒绝添加MQTT通知

**目标**：审批拒绝时也能推送MQTT通知到设备端

**实施步骤**：
1. 在 `approvals_routes.py` 的 `/reject` 端点添加MQTT通知逻辑
2. 使用与审批通过相同的通知格式，status字段设为'rejected'

**文件修改**：
- `backend/api/scores/approvals_routes.py`

**验证标准**：
- [ ] 审批拒绝后能在设备端收到通知
- [ ] 通知包含拒绝原因（comment字段）

### 3.2 积分录入校验规则限制

**目标**：创建积分记录时校验规则的每日上限和最小间隔

**实施步骤**：
1. 在 `records_routes.py` 中添加 `check_rule_limits()` 函数
2. 在 `score-entry` POST接口中调用校验函数
3. 返回明确的错误提示信息

**文件修改**：
- `backend/api/scores/records_routes.py`

**验证标准**：
- [ ] 超过每日上限时返回错误提示
- [ ] 未达到最小间隔时返回剩余等待时间
- [ ] 正常情况下不受影响

## 四、第二阶段实施计划（性能优化）

### 4.1 综合评分批量查询优化

**目标**：使用批量查询替代逐个查询，减少数据库访问次数

**实施步骤**：
1. 批量获取所有用户的学业成绩（使用聚合查询）
2. 批量获取所有用户的开锁记录（使用聚合查询）
3. 重构 `calculate_composite_score()` 方法

**文件修改**：
- `backend/services/composite_score_service.py`

**验证标准**：
- [ ] 查询次数从 O(n) 降为 O(1)
- [ ] 计算时间减少50%+

### 4.2 统计接口添加缓存

**目标**：为积分统计接口添加缓存机制

**实施步骤**：
1. 在 `/statistics` GET接口中添加缓存逻辑
2. 设置合理的缓存过期时间（5分钟）
3. 积分变动时自动失效缓存

**文件修改**：
- `backend/api/scores/records_routes.py`

**验证标准**：
- [ ] 相同条件的连续请求返回缓存数据
- [ ] 积分变动后缓存自动失效

### 4.3 审批列表分页

**目标**：为审批列表接口添加分页支持

**实施步骤**：
1. 修改 `/approvals/` GET接口支持分页参数
2. 修改 `/approvals/pending` GET接口支持分页参数

**文件修改**：
- `backend/api/scores/approvals_routes.py`

**验证标准**：
- [ ] 支持 page、per_page 参数
- [ ] 返回 total、pages 字段

## 五、第三阶段实施计划（高级功能）

### 5.1 审批超时提醒机制

**目标**：审批请求超时时发送提醒通知

**实施步骤**：
1. 在 `tasks/scheduled_tasks.py` 中添加定时任务
2. 检查超过24小时未处理的审批请求
3. 发送MQTT通知提醒管理员

**文件修改**：
- `backend/tasks/scheduled_tasks.py`

**验证标准**：
- [ ] 定时任务每小时执行一次
- [ ] 超时审批发送提醒通知

### 5.2 排名变动通知

**目标**：学生积分变化导致排名变动时发送通知

**实施步骤**：
1. 在积分变动时记录旧排名和新排名
2. 排名变动超过阈值时发送通知
3. 通过MQTT推送到设备端

**文件修改**：
- `backend/api/scores/records_routes.py`

**验证标准**：
- [ ] 排名上升时发送通知
- [ ] 排名下降时发送通知

### 5.3 综合评分增量更新

**目标**：支持按单个用户重新计算综合评分

**实施步骤**：
1. 添加 `recalculate_user_score(user_id)` 方法
2. 修改积分变动逻辑，触发单个用户重算
3. 更新数据库中对应记录

**文件修改**：
- `backend/services/composite_score_service.py`

**验证标准**：
- [ ] 单个用户积分变动后综合评分实时更新
- [ ] 不影响其他用户数据
