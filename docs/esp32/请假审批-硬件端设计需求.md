## 0. 评估结论（可行性）

| 项 | 结论 |
|----|------|
| **能否通过硬件完成？** | ✅ **可以**。设备侧仅约 5 处小改动（订阅 1 个 topic、按 `type` 分发 3 类回包、扩展刷卡菜单、给现有 query/unlock 回包加 2 个字段），全部状态/审批/计分/过期判定均在后端既有架构闭环。 |
| **审批能力是否从零新建？** | ❌ **否**。后端已存在 `Approval` 审批模型（含 `leave_type` / `start_date` / `end_date` / `student_id`，P0-4 已并入请假明细），且教师审批 REST 端点（`ApprovalApprove` / `ApprovalReject` / `ApprovalBatchApprove` 等）已齐备。**设备端对「审批」零感知**——后端把 `leave/req` 映射成一条 `Approval(type='leave')`，班主任在既有看板审批，设备下次 `leave/query` 自然看到 `approved/rejected`。 |
| **主要风险** | 原硬件计划「审批」一半偏弱（仅一句话「复用 Approval 体系」），且另提独立 `leave_records` 表与现有 `Approval` 模型**大量重叠**。字段冻结前必须先解决「复用/扩展 Approval 还是新建平行表」的架构决策（见 §2.4、§6）。 |
| **设备改动侵入性** | 低。完全沿用 `phonebox/` topic 规范 + `msg_id` 幂等信封 + 下行 `device_id` 定向，不动 query/unlock 主流程，仅在回包**追加**字段（老固件忽略，向后兼容）。 |

## 1. 责任边界（后端 vs 设备）

- **设备 = 哑终端**：只发起请求、展示回包、做本地 UI/串口交互；**不存储任何请假状态、不做请假/审批判定**。
- **后端 = 权威**：请假状态机、审批流（班主任看板）、过期任务、免扣分判定、班级级配置开关、审计，全部在后端。
- 设备只需保证：① 上行带齐 `msg_id/client_id/device_id/card_id`；② 下行按 `type` 分发并上屏 `r.explain`；③ 超时/断线不自动重发（防重复申请）。

## 2. 对原硬件计划的评估意见（逐条）

| # | 原文档条目 | 结论 | 后端处理 / 要求 |
|---|-----------|------|----------------|
| 2.1 | Topic 命名 `phonebox/leave/req\|cancel\|query` + 回包 `phonebox/leave/{device_id}` | ✅ 通过 | 与现有 `phonebox/query\|unlock\|points/*\|ota/*` 同构，回包定向 topic 与 `phonebox/ota/{device_id}` 同构，**无冲突**。设备按本文件 §3.1 实现。 |
| 2.2 | `msg_id` 幂等去重（沿用 §4.3） | ✅ 通过（须改写法） | **必须复用既有 `ProcessedMessage`（字段 `message_id` 设 `UNIQUE`）做原子去重**，插入捕获 `IntegrityError`；禁止 ad-hoc「先查后插」（QoS1 重投可致双插请假记录）。 |
| 2.3 | 「审批模式等班主任批（复用 Approval 体系）」 | ⚠️ **阻塞项（原文档空白）** | 审批端点后端**已存在**（`approvals_routes.py`）。后端将 `leave/req` 落成 `Approval(type='leave', status='pending')`；班主任在既有看板审批，状态翻转后设备 `leave/query` 反射。**设备无需为审批做任何额外实现**，但 §3.3 的 `r.status` 取值须与 `Approval.status` 对齐（`pending/approved/rejected`）。 |
| 2.4 | 新表 `leave_records` | ⚠️ **架构决策（重叠）** | 后端已有 `Approval(leave_type, start_date, end_date, student_id, status, approver_id)`。**不建议新建平行 `leave_records`**。决策二选一，冻结前须定（见 §6）：<br>(A) **扩展 `Approval`**：增 `start_time`/`end_time`(DateTime)、`card_id`、`device_id`，请假即一条 `Approval`；<br>(B) 新建薄表 `leave_records` 仅存运行态（`card_id/device_id/end_time/approver`），FK→`Approval.id` 关联审批。无论哪种，设备上行/下行字段不变。 |
| 2.5 | 伪代码混用 Python `now()` 与 SQLite `datetime('now','localtime')` | ⚠️ **风险（时区错位）** | 统一用后端 canonical `now()`（与中国时区一致，沿用「服务器时钟权威」约定）。所有 `end_time` 比较走后端 `now()`，禁止在业务代码里用 SQLite `localtime`。回包 `end_time` 用 **ISO8601 带时区偏移**（见 §2.10）。 |
| 2.6 | 请假中开箱「免扣 10 分」 | 💡 **建议优化** | 原规则：请假中开箱扣 0 分。存在滥用面（请了假仍来开箱白嫖免扣）。建议改为**可配置**：<br>· 默认 `auto_checkin_on_open=true`：请假中开箱 = **自动销假 + 正常扣 10 分**（学生既已返校，恢复正常规则）；<br>· 备选 `exempt_deduction=true`：保留纯免扣。两开关挂在 §2.7 的班级策略。 |
| 2.7 | 审批开关 `LEAVE_NEED_APPROVAL` 全局 | 💡 **建议改为每班级** | 现有 `PhoneBoxPolicy` 已按 `class_info_id` 配置（`allow_self_unlock` / `unlock_windows`）。请假审批与免扣分应同维度，新增 `leave_approval_required` / `leave_exempt_deduction` 两个布尔列挂 `PhoneBoxPolicy`，**非全局开关**。 |
| 2.8 | 销假仅学生自助 | 💡 **建议补教师代销假** | 看板需支持班主任手动取消（置 `cancelled`，`approver`=教师）。设备端无需变动（学生仍可刷卡自销）。 |
| 2.9 | 过期执行方式（定时 / 惰性） | 💡 **建议双保险** | 用现有任务基础设施做**周期性过期任务**（每分钟扫 `status='approved' AND end_time<=now()` → `expired`）；同时在 `leave/query` 与 unlock 判定时**惰性补过期**，避免看板/判定出现 stale「approved」。 |
| 2.10 | `end_time` 格式「ISO8601 或 YYYY-MM-DD HH:MM」 | ✅ 通过（收紧） | 强制 **ISO8601 带时区偏移**，如 `2026-10-04T18:00:00+08:00`。设备仅展示不解析，`remaining_hours` 由后端算好下发。 |
| 2.11 | 并发双插 | ⚠️ **风险** | 见 2.2：INSERT 走 `ProcessedMessage` 同款原子去重（先插 `ProcessedMessage(message_id)` 成功才写请假记录，否则原样重发首次回包）。 |
| 2.12 | query/unlock 回包追加 `on_leave` / `points_deducted` | ✅ 通过 | 加在现有 `publish_unlock_result` 的 payload（`result/reason/current_score/[device_id]`）中，老固件忽略新字段 → **向后兼容 OK**。设备按需解析 `on_leave` 标注「请假中·免扣分」。 |

## 3. 硬件端必须实现的接口（冻结基线）

### 3.1 Topic 清单（确认无冲突）

| 方向 | Topic | QoS | 触发时机 |
|------|-------|:---:|----------|
| 设备→后端 | `phonebox/leave/req` | 1 | 学生刷卡后在设备提交请假 |
| 设备→后端 | `phonebox/leave/cancel` | 1 | 学生返校刷卡确认销假 |
| 设备→后端 | `phonebox/leave/query` | 1 | 刷卡时设备查该生请假状态（UI 展示） |
| 后端→设备 | `phonebox/leave/{device_id}` | 1 | 以上三类统一回包（定向，按 `type` 区分） |

> 设备只需订阅自己的 `phonebox/leave/{device_id}`，重连时自动重订。

### 3.2 上行消息字段

#### 3.2.1 请假申请 `phonebox/leave/req`
```json
{
  "msg_id": "msg_pbB8F8626222D0_123",
  "client_id": "pbB8F8626222D0",
  "device_id": "pbB8F8626222D0",
  "card_id": "04A3B2C1",
  "leave_type": "sick",
  "leave_hours": 4
}
```
| 字段 | 类型 | 必填 | 说明 |
|------|------|:---:|------|
| `msg_id` | string | ✅ | 幂等去重（复用 `01-MQTT通信协议.md` §4.3，后端经 `ProcessedMessage` 原子去重） |
| `client_id` | string | ✅ | = `device_id` |
| `device_id` | string | ✅ | 发起设备（下行定向校验，G1 约定） |
| `card_id` | string | ✅ | 学生卡号（刷卡获得；后端据此解析 `student_id`） |
| `leave_type` | string | ✅ | `sick` 病假 / `personal` 事假 / `other` 其他 |
| `leave_hours` | int | ✅ | 时长（小时），UI 选项 `2 / 4 / 8 / 24` |

#### 3.2.2 销假 `phonebox/leave/cancel`
```json
{ "msg_id": "...", "client_id": "...", "device_id": "...", "card_id": "04A3B2C1" }
```

#### 3.2.3 状态查询 `phonebox/leave/query`
```json
{ "msg_id": "...", "client_id": "...", "device_id": "...", "card_id": "04A3B2C1" }
```

### 3.3 下行回包 `phonebox/leave/{device_id}`（按 `type` 分发）

#### 3.3.1 请假申请回包 `type=leave_req`
```json
{
  "device_id": "pbB8F8626222D0",
  "type": "leave_req",
  "r": {
    "ok": true,
    "status": "approved",
    "end_time": "2026-10-04T18:00:00+08:00",
    "explain": "请假已生效，截止今天 18:00"
  }
}
```
| 字段 | 取值 / 说明 |
|------|------------|
| `r.ok` | false = 卡号未注册 / 已有生效请假 / 审批被拒等 |
| `r.status` | `pending` 待审批 / `approved` 已生效 / `rejected` 已拒绝 / `duplicate` 已有生效请假 |
| `r.end_time` | ISO8601 带时区偏移，设备仅展示 |
| `r.explain` | 给学生看的一句话，设备直接上屏 |

失败示例：
```json
{ "device_id":"pbB8F8626222D0", "type":"leave_req",
  "r":{ "ok":false, "status":"duplicate", "end_time":"2026-10-04T18:00:00+08:00",
        "explain":"已有生效请假（病假），截止今天18:00，如需修改请先销假" } }
```

#### 3.3.2 销假回包 `type=leave_cancel`
```json
{ "device_id":"pbB8F8626222D0", "type":"leave_cancel",
  "r":{ "ok":true, "status":"cancelled", "explain":"销假成功，恢复手机存放" } }
```
| `r.status` | 场景 |
|------------|------|
| `cancelled` | 销假成功 |
| `not_found` | 该生无生效请假（`ok=false`） |

#### 3.3.3 状态查询回包 `type=leave_status`
```json
{ "device_id":"pbB8F8626222D0", "type":"leave_status",
  "r":{ "on_leave":true, "leave_type":"sick", "status":"approved",
        "end_time":"2026-10-04T18:00:00+08:00", "remaining_hours":3.5 } }
```
| 字段 | 说明 |
|------|------|
| `r.on_leave` | 当前是否处于生效请假中（approved 且未过期） |
| `r.status` | 同 3.3.1（请假中显示 `approved`，待审批显示 `pending`） |
| `r.remaining_hours` | 剩余小时数（浮点 1 位，后端算好） |
| `on_leave=false` 时其余字段可省略 | |

### 3.4 query/unlock 回包新增字段（向后兼容）

学生刷卡 → 设备发 `phonebox/query` → 后端 `publish_unlock_result` 回包**追加**：
| 新增字段 | 类型 | 说明 |
|----------|------|------|
| `on_leave` | bool | 该生是否生效请假中（无请假历史 = false） |
| `points_deducted` | int | 本次实际扣分：正常 `10`，请假免扣 `0`（若采用 §2.6 自动销假，则为 `10` 且 `on_leave` 转 false） |

> 老固件不解析新字段，行为不变；新固件据 `on_leave` 在 UI 标注「请假中·免扣分」。

## 4. 设备端行为规格

### 4.1 刷卡后菜单（量产板有屏后启用）
```
刷卡 → query 回包 on_leave
  ├─ on_leave=false → [1] 开箱  [2] 请假
  └─ on_leave=true  → 张三（请假中·病假）
                    剩余 3.5 小时
                    [1] 开箱（免扣分）  [2] 销假
```
- 「请假」→ 进入类型+时长选择（sick/personal/other × 2/4/8/24h）→ 发 `leave/req`。
- 「销假」→ 二次确认 → 发 `leave/cancel`。

### 4.2 串口调试命令（先于 UI 实现，无屏调试用）
| 命令 | 等效操作 |
|------|----------|
| `leave sick 4` | 提交病假 4 小时 |
| `leave personal 8` | 提交事假 8 小时 |
| `leave cancel` | 销假 |
| `leave query` | 查状态 |

### 4.3 超时 / 断线 / 失败
| 场景 | 设备行为 |
|------|----------|
| 发送后 3s 无回包 | UI/串口提示「网络超时，请重试」，**不自动重发**（防重复申请；后端 `msg_id` 去重兜底） |
| 回包 `ok=false` | 直接上屏 `r.explain` |
| MQTT 断线 | 提示「离线，暂无法请假」 |

### 4.4 兼容性
- 老固件忽略 `phonebox/leave/{device_id}` 回包中的新增字段及 `query/unlock` 的 `on_leave`/`points_deducted`，行为不变。
- 设备订阅 `phonebox/leave/{device_id}` 失败不影响既有 `query/unlock/heartbeat/points/ota` 功能。

## 5. 联调验收用例

### 5.1 设备侧（L1–L10，沿用原硬件计划）
| 用例 | 操作 | 预期 |
|------|------|------|
| L1 正常请假 | 串口 `leave sick 4` | 回包 ok=true status=approved（免审批模式）或 pending（审批模式），DB 新增记录 |
| L2 重复请假 | 连续两次 `leave sick 4` | 第二次 ok=false status=duplicate，返回已有 end_time |
| L3 请假中开箱 | L1 后刷卡开箱 | unlock 回包 on_leave=true；points_deducted 按 §2.6 配置（0 或 10） |
| L4 销假 | `leave cancel` | ok=true status=cancelled，再开箱恢复标准扣分 |
| L5 无记录销假 | 直接 `leave cancel` | ok=false status=not_found |
| L6 过期 | 造 end_time 已过的记录 | 周期性/惰性任务置 expired，开箱恢复扣分 |
| L7 状态查询 | `leave query` | 请假中 on_leave=true+remaining；否则 on_leave=false |
| L8 未注册卡 | 未知卡 `leave sick 4` | ok=false「卡号未注册」 |
| L9 网络超时 | 断 broker 后 `leave sick 4` | 设备 3s 超时提示，不重发 |
| L10 幂等 | 同 msg_id 重放 | 后端原子去重拦截，不重复入库 |

### 5.2 后端补充（B 系列，不属设备职责但须联调）
| 用例 | 预期 |
|------|------|
| B1 教师审批流 | `leave/req`（审批模式）落 `Approval(type='leave', status='pending')` → 教师看板 `ApprovalApprove` → 状态转 approved → 学生 `leave/query` 见 approved |
| B2 跨设备销假 | A 设备请假、B 设备刷卡销假，cancel 按 card_id 命中（不依赖 device_id） |
| B3 时区边界 | 构造跨零点 end_time，后端 now() 与回包偏移一致，不出现早过期/不过期 |
| B4 自动销假（若采用 §2.6） | 请假中开箱 → 自动 cancelled + 正常扣 10 分 |
| B5 每班级配置 | 甲班 `leave_approval_required=true`、乙班 false，分别走审批/直生效 |
| B6 教师代销假 | 看板教师手动 cancel 学生请假，approver=教师 |
