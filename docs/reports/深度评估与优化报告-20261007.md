## 1. 评估方法

采用三层递进，避免"扫描即改"导致的误报式破坏：

1. **AST 静态扫描**（脚本 `/tmp/ast_assess.py`，临时不入库）：
   - N+1 检测：在 `for` 循环体内出现 DB 查询且该查询引用循环变量；
   - 缺失索引检测：模型元数据 + 迁移脚本 `get_all_indexes()` 的索引并集，对比真实 `filter`/`order_by` 出现的列；
   - 静默异常检测：`except` 块内无 `raise` 且吞掉异常的 broad 捕获。
2. **抽样读码甄别**：对扫描命中的候选逐条读源码，区分"真实热点"与"误报"（如 PK `get` 单点、内存字符串处理、测试专用路径）。
3. **修复 + 回归**：仅对确证为高价值、低风险的项执行修复，全部走模型元数据或局部批量化（不引入新依赖、不改 API 契约），以定向测试 + 全量回归（`run_regression_batched.py`，21 分块 subprocess，各写 junitxml）证明零破坏。

## 3. 已确认的真实缺陷（定位 + 量化）

### 3.1 `warning_service.evaluate_risk` — 严重 N+1（头号优化）
- **位置**：`services/warning_service.py` `evaluate_risk`（原 L59–127）。
- **问题**：对每个 `user` 在循环体内各发 4 次 DB 查询：`_get_no_positive_days` / `_get_today_unlock_count` / `_get_student_avg_score` / `CompositeScore.query.filter_by`。
- **量化**：50 名学生 ≈ **200+ 次查询**（原实现每生最多 30 次按天循环 + 多轮查询）；班级规模越大线性放大。
- **风险**：管理后台"风险评估"接口随学生数增长显著变慢，且 `_get_today_unlock_count` 原实现用 `len(.count())` 会抛 `TypeError` 导致接口整体 500。

### 3.2 五个缺失索引（按命中频次排序）
| 模型.列 | 命中 filter/order_by 次数 | 表规模 | 优先级 |
|---|---|---|---|
| `NLPScoringRule.score_type` | 10 | 中 | 高 |
| `User.role` | 7 | 最大表 | 高 |
| `Exam.date` | 4 | 大 | 中 |
| `Admin.real_name` | 3 | 小 | 中 |
| `CourseSchedule.(class_info_id, day_of_week, period_number)` | 课表查询复合条件 | 大 | 中 |

> 全部为真实存在的列、无命名冲突；既有索引并集（17 个）未覆盖上述列/组合。

## 4. 已执行的优化（低风险、零契约变更）

### 4.1 N+1 重构 — `services/warning_service.py`
将"逐用户 4 次查询"改为 **3 次批量查询 + 内存分组**：

```python
user_ids = [u.id for u in users]
since = datetime.now() - timedelta(days=30)
today = datetime.now().date()
today_start = datetime(today.year, today.month, today.day)

sr_rows = ScoreRecord.query.filter(
    ScoreRecord.student_id.in_(user_ids),
    ScoreRecord.created_at >= since,
).all()
sr_by_user = {}
for _r in sr_rows:
    sr_by_user.setdefault(_r.student_id, []).append(_r)

score_rows = Score.query.filter(Score.student_id.in_(user_ids)).all()
score_by_user = {}
for _s in score_rows:
    score_by_user.setdefault(_s.student_id, []).append(_s)

comp_rows = CompositeScore.query.filter(
    CompositeScore.student_id.in_(user_ids)
).all()
comp_by_user = {_c.student_id: _c for _c in comp_rows}
```

循环体内改为 O(1) 字典查（`sr_by_user.get(user.id, [])` 内算 `positive_dates`/`daily_unlock_count`、`score_by_user` 算 `avg_score`、`comp_by_user.get(user.id)`）。
- 新增纯函数 `_consecutive_no_positive_days(positive_dates, today=None)`，`_get_no_positive_days` 委托它，**保持既有单测不变**。
- 修复原 `_get_today_unlock_count` 的 `len(.count())` 隐患（现方法内已规避，且批量化后该路径不再被 `evaluate_risk` 走）。
- **查询次数**：50 学生从 ~200+ 降至固定 **3 次批量 + 内存计算**，与班级规模解耦。

### 4.2 五个缺失索引 — 全部走模型元数据（幂等补建，无需手写迁移）
| 文件 | 改动 |
|---|---|
| `models/user_models.py` | `User.role` → `db.Column(db.Text, index=True)`；`Admin.real_name` → `db.Column(db.String(50), index=True)` |
| `models/nlp_models.py` | `NLPScoringRule.score_type` → `db.Column(db.String(20), index=True)` |
| `models/score_models.py` | `Exam.date` → `db.Column(db.DateTime, index=True)`；`CourseSchedule` 增 `__table_args__ = (db.Index("ix_course_schedule_class_day_period", "class_info_id", "day_of_week", "period_number"),)` |

> 索引由 `migrations/reconcile.py` 在启动时按模型元数据**幂等补建**（沙箱测试库 `create_all` 已纳入，现有索引由 17 → 22）；不新增 Alembic 迁移、不改任何写路径契约。

### 4.3 未改动项
- `warning_service._calculate_risk_score`（L193）：本文件内无调用点，非热点，保持现状。
- 其余 131 处 N+1 候选、77 处静默异常：经甄别为误报或业务兜底，不纳入本轮（避免引入回归风险）。
