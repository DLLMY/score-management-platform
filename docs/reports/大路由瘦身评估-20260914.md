# 大路由瘦身（读路径编排下沉）收益 / 回归面评估方案

- 日期：2026-09-14
- 触发：用户对上一轮 P0/P2/P3 复盘收尾时提出「需要针对大路由瘦身（读路径编排下沉）单独出一份收益/回归面评估方案」
- 结论速览：**Aug-21 报告点名的 `records`/`algorithm` 两项已不再是重点**，剩余体量为结构性（多端点 / 编排胶水），非有害型胖路由；真正高内联 DB 的路由（rbac/devices/firmware 等）均属高敏感 / 高关键模块，回归成本 >> 收益，建议不盲目重构。

## 1. 测量方法

- 扫描范围：后端 `apps/backend` 全部 `*routes*.py`（含 `api/**` 与 `tests/**`，共 112 个文件；评估以 `api/**` 为准，`tests/**` 仅作参照）。
- 指标：
  - `tot`：文件总行数（体量）
  - `dbops`：全文件内联 DB 操作模式命中数（`db.session.*`、`Xxx.query.`、`.filter(`、`.filter_by(`、`.order_by(`、`.paginate(`、`.all()`、`.first()`、`.count()`、`db.session.begin()` 等）—— 衡量「路由层是否在做本应在 service 的读/写编排」
  - `fns` / `maxlen` / `>60`：函数数量、最长函数行数、超 60 行函数数（衡量单函数复杂度）
- 工具：AST + 正则，脚本为一次性临时脚本（已清理）。

→ Aug-21 报告「大路由瘦身(records/algorithm)」指向的状态**已不存在**；当前残留体量属结构性，无害。

## 4. 逐项 ROI / 回归面分析

### 4.1 `rbac_routes.py`（105 内联 DB）— ⚠️ 高回归成本，不建议动
- **收益**：下沉权限查询逻辑到 `rbac_service`，可提升复用与单测覆盖。
- **回归面**：RBAC 是安全底座，改后**必须**重跑 `verify_rbac_consistency.py --check-only`（G2 闸门：G2 68 / DB 70 / seed 66 / teacher 30），任何权限词根遗漏即触发班级隔离 `_CLASS_SCOPE_PREFIXES` 自动 403。
- **结论**：除非出现具体 RBAC bug，否则**收益 < 回归风险**，建议保持现状。

### 4.2 `devices_routes.py`（1423 行 / 52 / 最大 123）— 中高成本
- **收益**：拆出 4 个 >60 行函数（含 123 行巨函数）到 `device_orchestration_service`，可降单文件复杂度。
- **回归面**：设备 MQTT 下发、心跳、认证全链路；改动需守「强杀重启 + 零回归闸门 + 不 git commit」。最大函数 123 行暗示历史累积逻辑，抽取易引入边界 bug。
- **结论**：**可评估但须单独拍板**，优先用「防腐层只迁读路径」铁律，写路径保持不动。

### 4.3 `firmware_routes.py` / `subject_routes.py` / `course_schedule_routes.py` / `users_routes.py` — 高关键、中成本
- 均为业务/学术/用户核心域；内联 DB 30 上下，说明**已部分下沉 service、残留少量聚合**。
- 回归面宽（覆盖全量用户日常操作），重构收益有限（逻辑已在 service，仅路由层少量胶水）。
- **结论**：**不建议 blanket 重构**；若做，仅在出现具体性能/可测性痛点时局部抽取。

### 4.4 `records_routes.py` / `algorithm_routes.py` — 已收口
- 见 §2，无需再投入。

## 5. 结论与建议

1. **Aug-21 报告的「大路由瘦身(records/algorithm)」已实质完成**：records 读路径下沉 `score_record_service`、algorithm 为零内联 DB 薄端点。该报告项可判定为**已收口 / 过时**。
2. **不建议发起 blanket 大路由瘦身**：当前真正高内联 DB 的路由（rbac/devices/firmware/subject/course_schedule/users）均属高敏感 / 高关键域，回归成本显著高于可测性/复用收益。
3. **若坚持要做**，仅建议两种低风险动作（需你单独拍板 + 零回归闸门）：
   - (a) `algorithm_routes.py` 纯机械拆文件（按域把 66 个端点类分到 `algorithm/` 下兄弟文件，不改逻辑）—— 仅改善导航，零行为变更；
   - (b) `records_routes.py` 把 5 个 >60 行编排胶水 helper（`post` 81/105、`delete` 100、`_notify_score_change` 67、`_notify_rank_change` 56、`_validate_batch_entry` 52）抽到 `score_record_orchestration.py` —— 可选 cosmetic，收益有限。
4. **绝不动**：rbac/devices/firmware/users/subject/course_schedule 的写路径与核心读聚合，除非出现具体缺陷且经你授权。
