## 一、为什么需要重新确认

原「未调用」判定**只扫描了前端 `api.ts`** 的调用，对后端内部调用、测试、运维脚本、设备/服务端回调完全不可见，误报率极高。因此对本批 55 条逐一做**全仓库引用核实**。

## 二、核实方法

1. 加载真实 Flask 应用，从 `app.url_map` 取出每条 G 路由的 view function 与资源类名。
2. 对整个仓库（前端 `src` / `backend/tests` / 后端内部调用 / 路由定义文件 / 运维脚本 / 文档 `docs`）做**路径 + 类名**双维度引用扫描。
3. **排除自引用**：路由定义文件本身必然含路径字符串，必须剔除，否则每条都「命中自己」产生假阴性。
4. 扫描结果分桶：FRONTEND / TEST / BACKEND_INTERNAL / ROUTE_DEF / OPS / SCRIPTS / DOCS。
5. 对仅命中 DOCS（弱引用）的边界项，**人工二次 grep 复核**（确认前端用的是 `/api/rbac/role-permissions` 而非根路径）。
