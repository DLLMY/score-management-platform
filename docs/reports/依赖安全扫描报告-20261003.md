## 3. 方法学与注意事项

1. **为什么用 PyPI 源而非默认 OSV 源**
   默认漏洞源（OSV）在本地沙箱内网络请求挂死（180s 前台超时 SIGTERM，疑似网络受限）。PyPI 官方漏洞库在沙箱内可稳定直连，故作为本次主源。
2. **Windows 绝对路径解析坑**
   以 `C:/.../requirements.lock.txt` 绝对路径传参时，argparse 将盘符 `C:` 误判为位置参数 `project_path`，报 `argument project_path: not allowed with argument -r/--requirement`。改用相对路径 + 短选项 `-s pypi` 解决，已记录供后续复用。
3. **前端 npm 审计未执行（环境限制，非风险）**
   `apps/frontend/package-lock.json` 存在，但本机 npm 配置指向 `registry.npmmirror.com`（淘宝镜像），该镜像**未实现安全审计端点**（`POST /-/npm/v1/security/audits/quick` 返回 `NOT_IMPLEMENTED`）。故前端侧 `npm audit` 无法在当前环境完成。
4. **缓存告警无害**
   扫描中出现的 `cachecontrol.controller: Cache entry deserialization failed` 仅为上一次被中断的 OSV 尝试遗留的本地缓存反序列化警告，不影响本次 PyPI 源结果。

| 维度 | 状态 | 建议 |
|---|---|---|
| 后端 Python（PyPI 源） | ✅ 已扫，干净 | —— |

| 前端 npm（官方源） | ⚠️ 镜像不支持审计 | 在可联网环境运行 `npm audit --registry=https://registry.npmjs.org`（于 `apps/frontend`） |
| 持续化 | ❌ 未接入 | 见下节 |

## 5. 后续加固建议（可选，非必修）

1. **CI / 预发布闸门**：在部署流水线中加入 `pip-audit -r requirements.lock.txt --fail-on HIGH`（或 `CRITICAL`），将漏洞扫描固化为发布硬门槛。
2. **定期复扫 + 依赖更新**：按月执行扫描；可引入 Dependabot / Renovate 自动提交依赖升级 PR（仅当维护策略允许）。
3. **补跑交叉源**：在具备公网访问的机器补跑 OSV 源与前端官方源审计，闭合覆盖范围。
4. **锁定文件纪律**：保持 `requirements.lock.txt` 为唯一事实来源（已有 `requirements.txt` / `requirements-ml.txt` 为分层声明），新增依赖必须经 `pip-compile` 重新锁定，避免引入未审计版本。

## 7. 加固已落地（2026-10-03）

对应 §5 建议，依赖安全扫描已从「一次性手动」固化为 **CI 自动化闸门**：

| 交付 | 路径 | 说明 |
|---|---|---|
| 可复用审计脚本 | `scripts/audit_deps.py` | 封装 pip-audit，规避沙箱踩过的坑（相对路径 `-r` 防止 Windows 盘符被误判为 `project_path`、默认 `--service pypi`、`--json` 强制绝对路径防落盘错位）；`--service osv` 可交叉校验 |
| CI 闸门 | `.github/workflows/dependency-audit.yml` | 每月 1 日定时复扫 + 依赖/审计配置变更时 push/PR 触发；后端 **PyPI 主闸门**（PR 发现漏洞即非零退出、阻断合入）+ **OSV 交叉**（仅告警，网络偶发不阻断）；前端强制官方源 `npm audit --registry=https://registry.npmjs.org/` |
| 部署/CI 对齐 | `.github/workflows/{ci,deploy}.yml` | 后端均使用 `requirements.lock.txt` 作为唯一事实来源，与审计源一致，新增依赖须经锁定后再合入 |

**效果闭环**：
- 后端漏洞扫描：手动 → 按月 + 变更触发的自动化闸门，PR 合入前拦截已知漏洞。
- 前端审计：在 CI 真机用官方源执行，绕过本机 npmmirror 镜像不支持审计端点的限制（§3.3）。
- OSV 交叉源：移至 CI 真机执行，闭合 §4 中「沙箱网络受限」未覆盖项。

本地复跑：`python scripts/audit_deps.py`（默认 pypi）；交叉 `python scripts/audit_deps.py --service osv`。
