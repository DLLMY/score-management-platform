# 生产运维 Runbook（自我管理提升 V2.0 管理平台）

- **版本**：v2.0
- **适用**：部署 / 启动 / 回滚 / 灾备 / 监控 / 应急
- **对齐**：`.github/workflows/{ci,deploy}.yml`、`apps/backend/config.py`、`app/metrics_exporter.py`
- **定位**：纯运维操作手册，**不描述业务功能**；任何源码改动须走「四闸门 + 零回归」铁律（见 `docs/下一步开发计划-20261003.md`）。

---

## 1. 系统架构概览

| 组件 | 技术 | 默认端口 | 说明 |
|---|---|---|---|
| 后端 API | Flask + Flask-RESTful + SocketIO | **5000** | 双 JWT 隔离 + 信封（envelope）封装；`create_app` 工厂 |
| 前端 | React 18 + Vite 6 + TS 5.9 | **3000**（dev） | 开发态 Vite 代理 `/api` → `127.0.0.1:5000` |
| 数据库 | **SQLite**（单文件） | —— | 默认 `apps/backend/instance/score_management.db` |
| 缓存 / 队列 | Redis 7 + Celery | 6379 | 异步任务、限流、会话缓存 |
| MQTT Broker | EMQX Cloud | 8883(TLS) | ESP32 设备接入、OTA 指令下发 |
| 反向代理 | nginx（TLS 终止） | 443 | P0-c 已落地：HTTPS 终止后反代到 5000 |

> 监控端点：后端暴露 **Prometheus 原生 `/metrics`**（免鉴权、受 `TESTING` 守卫）与 **flask-restx Swagger `/swagger/`**（API 文档，见 `docs/api/`）。

## 2. 关键环境变量（后端）

| 变量 | 默认 | 说明 |
|---|---|---|
| `APP_ENV` | development | 运行环境（production/development） |
| `FLASK_HOST` / `FLASK_PORT` | 127.0.0.1 / 5000 | 监听地址与端口 |
| `DATABASE_URI` | `sqlite:///<basedir>/instance/score_management.db` | SQLite 连接；支持 `sqlite:///` 绝对/相对路径覆盖 |
| `FLASK_SECRET_KEY` | 自动生成（不持久） | **生产必须显式设定**，否则重启后签名失效 |
| `ADMIN_INIT_PASSWORD` | —— | 首启动管理员初始密码（种子） |
| `MQTT_BROKER` / `MQTT_PORT` / `MQTT_USERNAME` / `MQTT_PASSWORD` | —— | EMQX Cloud 接入凭据 |
| `REDIS_URL` | —— | Redis 连接串 |

> ⚠️ 生产部署 **必须** 固化 `FLASK_SECRET_KEY`、`DATABASE_URI`、`ADMIN_INIT_PASSWORD`、MQTT/Redis 凭据；通过 **CI/CD secrets** 注入，**严禁明文入库**（见 `deploy.yml` 中 `secrets.*` 注入方式）。

## 3. 部署（对齐 CI/CD）

部署流水线（`.github/workflows/deploy.yml`）骨架：
1. **构建**：CI 用 `requirements.lock.txt`（确定性锁，116 个 pin 包）安装后端依赖；前端 `npm install --legacy-peer-deps` + `npm run build` 产出静态资源。
2. **发布门控（P0-d 迁移闸门）**：发布前在目标环境跑
   ```bash
   python -c "from app import create_app; from app.db_init import init_database; \
              app = create_app(); init_database(app); print('schema reconcile done')"
   ```
   该步幂等对账（补齐缺失表/列/索引 + 默认种子），失败即阻断发布。
3. **上线**：拉取产物 → 安装锁文件依赖 → 启动后端 + nginx 反代。

> `deploy-linux` / `deploy-windows` job 当前 `if: false`（待配置服务器 SSH 后启用）。启用前需补齐 `secrets`：服务器主机/用户/密钥、`SQLALCHEMY_DATABASE_URI`、`ADMIN_INIT_PASSWORD`、MQTT 四件套。

## 4. 启动与重启

### 4.1 开发 / 单机
```bash
# 后端（开发态）
cd apps/backend
python run.py --env development --host 127.0.0.1 --port 5000

# 前端（开发态，另开终端）
cd apps/frontend
npm run dev        # Vite 监听 3000，代理 /api → 127.0.0.1:5000
```

### 4.2 生产
- 后端以 **WSGI/ASGI 进程**（如 gunicorn + eventlet 适配 SocketIO）常驻，由 systemd/supervisor 守护，nginx 反代 `127.0.0.1:5000`。
- 前端 `npm run build` 产出 `dist/`，由 nginx 直接托管静态文件并对 `/api` 反代后端。

### 4.3 ⚠️ 后端代码变更重启铁律
> **改后端必须强杀全部 python 进程再重启**——SocketIO 不响应 reload，热重载会残留旧事件回路导致双实例/端口占用。

```bash
# Windows
taskkill /F /IM python.exe
# Linux
pkill -f "run.py"   # 或按端口定位：fuser -k 5000/tcp
# 再重新拉起 4.1 / 4.2 的启动命令
```

## 5. 数据库（SQLite）运维

- **位置**：`apps/backend/instance/score_management.db`（默认），或 `DATABASE_URI` 指定的任意 `sqlite:///` 路径。
- **在线兜底**：SQLite 单文件，写操作串行（`connect_args.timeout=30`）。

### 5.1 备份（推荐每日低峰 + 发布前）
```bash
# 在线拷贝即可（SQLite 保证拷贝一致性；建议短暂停止写流量更稳妥）
cp apps/backend/instance/score_management.db \
   /backup/score_management_$(date +%Y%m%d_%H%M).db
```
> 更稳妥：先 `sqlite3 <db> .backup '/backup/xxx.db'`（热备原子快照）。

### 5.2 恢复
```bash
# 停后端 → 替换文件 → 重启
systemctl stop score-backend          # 或 4.3 的强杀
cp /backup/score_management_YYYYMMDD_HHMM.db apps/backend/instance/score_management.db
# 重启（见 4.3）
```

### 5.3 启动自动对账（P0-d，**勿手动跑迁移脚本**）
后端启动经 `init_database()` 自动执行 `reconcile`（元数据驱动）+ `seed_defaults`（幂等种子：12 默认节次 + 5 预警配置）。**legacy `migrations/*.py` 已弃用**，切勿手动 `ALTER`——全新库由 `create_all` + reconcile 维护 schema。

## 6. Redis / Celery / EMQX

| 组件 | 检查 | 重启 |
|---|---|---|
| Redis | `redis-cli ping` → `PONG` | 依部署方式（systemd / 容器） |
| Celery | 确认 worker 进程存活；失败任务入 broker 重试 | 重启 worker：`celery -A <app> worker --loglevel=info` |
| EMQX Cloud | 控制台查看连接数 / 上行消息 | 由云服务商托管，检查凭据与 TLS 8883 连通性 |

> ESP32 OTA：设备 `device_type` 维度已就绪（phonebox 已闭环；doorlock 待固件）。后端协商/推送链路见 `docs/esp32/`。

## 8. 回滚

| 场景 | 操作 |
|---|---|
| 代码回归 | Git 回退到上一个健康 tag（`git revert` 或 `git checkout <sha>`）→ 重新构建/部署；CI 全回归需先本地跑通 |
| 数据库 schema 异常 | 用 5.2 恢复最近备份；`reconcile` 幂等，重跑不破坏既有数据 |
| 配置错误 | 回退 `secrets`/环境变量到上一版；`FLASK_SECRET_KEY` 回退后需用户重新登录（JWT 失效） |

> 回滚前务必保留当前态备份（DB + 构建产物），避免二次事故。

## 9. 灾备

- **数据库**：每日异地备份 `instance/score_management.db`（见 5.1），保留 ≥ 7 天滚动。
- **构建产物**：CI 每次发布产出 Release 产物（GitHub Releases），可随时重新拉取。
- **密钥**：`secrets` 独立于代码仓库，灾备时从密钥管理器恢复，**不依赖代码库**。
- **演练**：每季度执行一次「备份恢复 + 回滚」演练，验证 RTO/RPO。

## 10. 应急止血清单

1. **服务不可用**：先查进程存活（4.3）→ 端口占用 → 日志；强杀重启。
2. **5xx 激增**：盯 `/metrics` 的 `flask_http_requests_total{status=~"5.."}` 与 `flask_exceptions_total`；看后端日志栈。
3. **延迟飙高**：看 `flask_http_request_duration_seconds` P95/P99；排查 DB 锁（`connect_args.timeout=30`）、Redis、外部 MQTT。
4. **MQTT 掉线**：查 EMQX Cloud 控制台、TLS 8883 连通、凭据有效期。
5. **数据损坏疑似**：停写 → 用最近备份恢复（5.2），勿手动修库。

## 11. 常见故障排查

| 现象 | 可能原因 | 处置 |
|---|---|---|
| 端口 5000 被占 | 旧 python 未杀净（SocketIO 不 reload） | 4.3 强杀后重启 |
| 登录全部失效 | `FLASK_SECRET_KEY` 未固化 / 重启变更 | 固化密钥到 secrets，重启 |
| 前端白屏 | 代理未指向 5000 / build 缺失 | 查 nginx 反代与 `dist/` |
| DB 写超时 | 长事务占锁 | 查慢查询；必要时备份恢复 |
| 依赖漂移报错 | 未用 `requirements.lock.txt` | 强制安装锁定文件，重新构建 |

## 12. 运维红线（铁律）

- **禁止** 手动改库 schema（legacy 迁移脚本已弃用；由 `reconcile` 维护）。
- **禁止** 后端热重载代替强杀重启（SocketIO 残留）。
- **禁止** 明文密钥入库；生产凭据走 CI/CD secrets。
- **任何源码改动** 必过四闸门（tsc/eslint/prettier/vitest + 后端 venv pytest 串行 3 批）与零回归，提交需显式确认（不自动 commit）。
