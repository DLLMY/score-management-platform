## 二、上一轮「重叠」判断的更正

上一轮我提示：

> `react-page-split` 与 `frontend-dead-code-removal` 存在职责边界重叠

**实测后此判断不成立，予以更正**：

| Skill | 核心动作 | 触发词 |
|-------|---------|--------|
| `react-page-split` | **拆**：600 行+ 巨型页 → 装配层 + 实现目录 + components/ | T12、巨型页拆分、god view、拆 View、拆 hook |
| `frontend-dead-code-removal` | **删**：无消费者 hook/组件/导出 | 删除未使用 hook、精简死导出、清理 barrel 再导出 |

两者一个「拆」一个「删」，动作相反、触发词无交叉、适用场景不同，**边界清晰**。

**唯一实质重复**：两者（及 `frontend-import-barrel-unification`）各自内嵌了一份「四闸门命令」段落（tsc / eslint / prettier / vitest 的 managed Node 直调路径）。

**建议**：这是**可接受的重复**——skill 自包含更可靠，不必强行 DRY；共享段落若未来出现版本漂移（如 Node 版本升级需改三处），再抽 `frontend-gates-reference` 不迟。**当前无需处理。**
