## 1. 方法论（四步闭环）

1. **提取真实索引定义**：遍历 `db.metadata.tables`，导出 83 张表的全部索引及列序。确认绝大多数为单列索引，仅 3 个复合索引：
   - `course_schedules(class_info_id, day_of_week, period_number)`
   - `operation_log(user_id, created_at)`
   - `score_record(student_id, created_at)`
   且三个复合索引的前导列均已有单列索引覆盖。
2. **静态扫描过滤列覆盖缺口**：AST 提取全部 `Model.query.filter / filter_by` 的过滤列（共 702 处使用），与其真实索引列比对，产出 **52 个「被过滤但无显式索引」候选**。
3. **隔离内存引擎实证审计**：构建最小 `Flask(__name__)` + `sqlite:///:memory:` + `db.init_app` + `db.create_all()`，**完全不触碰开发库**（规避 `create_app('testing')` 连开发库触发 `create_indexes` 建索引、乃至 `db.drop_all()` 的风险）。用代表性数据（目标列逐行赋唯一值 `%s_%d` 避免 UNIQUE 碰撞）对 52 个候选逐个跑 `EXPLAIN QUERY PLAN`，区分 `SCAN table`（FULL-SCAN，真债）与 `SEARCH table USING INDEX`（索引查找，非债）。
4. **甄别真实债**：结合表体积增长特征（是否只增不删、是否高频按该列查询）与字段基数，排除 tiny-table 与低基数字段的「优化器跳过索引」正常现象，仅修复确凿 FULL-SCAN 债。

## 2. 关键修正：纠正第六轮前的静态分析误判

早期静态扫描（仅查显式 `Index` 对象）曾将以下列列入「疑似缺索引」名单。本轮用隔离引擎实证 `EXPLAIN` 后确认它们**本就走索引、非债**，不应加索引（加索引徒增写放大）：

| 列 | 实证结论 | 原因 |
|----|----------|------|
| `admin.username` | `SEARCH USING INDEX sqlite_autoindex_admin_1` | `UNIQUE` 约束自动生成隐式唯一索引 |
| `sub_account.username` | `SEARCH USING INDEX sqlite_autoindex_sub_account_1` | 同上 |
| `processed_message.message_id` | `SEARCH USING INDEX sqlite_autoindex_processed_message_1` | 同上（MQTT 去重热路径，表只增不删，但已有 UNIQUE 护体） |
| `subject.code` | `SEARCH USING INDEX sqlite_autoindex_subject_1` | 同上 |
| `subject.name` | `SEARCH USING INDEX sqlite_autoindex_subject_2` | 同上 |

> 教训：**`UNIQUE` 约束会自动生成 `sqlite_autoindex_<table>_N` 隐式唯一索引**，静态扫描只查显式 `Index` 对象会漏判，必须以 `EXPLAIN` 实证为准。

## 3. 确凿 FULL-SCAN 真实债（已修复）

### 3.1 `Device.mac_address` → `index=True`
- **路径**：WOL（Wake-on-LAN）、设备识别、心跳/在线状态判断等热路径按 `mac_address` 查询。
- **实证**：修复前 `EXPLAIN QUERY PLAN ... WHERE mac_address = :v` 返回 `SCAN device`（FULL-SCAN）。
- **修复**：`apps/backend/models/device_models.py` L174
  ```python
  # 修复前
  mac_address = db.Column(db.String(20))
  # 修复后
  mac_address = db.Column(db.String(20), index=True)
  ```
- **实证（修复后）**：`SEARCH device USING INDEX ix_device_mac_address`。

### 3.2 `DeviceHeartbeat.device_id` → `index=True`
- **路径**：按设备查最新心跳 / 在线状态，是高频查询；该表**每几秒写入一条、只增不删**，随设备运行时间增长表迅速膨胀，无索引时全表扫描成本线性上升。
- **实证**：修复前 `EXPLAIN QUERY PLAN ... WHERE device_id = :v` 返回 `SCAN device_heartbeat`（FULL-SCAN）。
- **修复**：`apps/backend/models/device_models.py` L246
  ```python
  # 修复前
  device_id = db.Column(db.String(100), nullable=False)
  # 修复后
  device_id = db.Column(db.String(100), nullable=False, index=True)
  ```
- **实证（修复后）**：`SEARCH device_heartbeat USING INDEX ix_device_heartbeat_device_id`。
