## 2. 修复方案（R24-1）

统一模式：把同一张表上的多个 COUNT / 嵌套时间窗计数，合并为**单条** `with_entities(func.count(id), func.sum(case((cond,1),else_=0)), ...).one()`；嵌套时间窗（`month ⊃ week ⊃ day` 或 `7d ⊃ 24h ⊃ all`）用单条 `>= start` + `case` 分档算各档。

最终落地 6 处的**实测**查询数（以通过的 harness 断言为准）：

| # | 函数 | 原查询 | 落地后 | 省 | 说明 |
|---|---|---|---|---|---|
| R24-1 | `get_dashboard_summary` | ScoreRecord 3 + User 3 | ScoreRecord **1** + User **2** | 3 | 月/周/日嵌套窗 → 1 条 case 分档；students 计数并入 class_list 分组 |
| R24-2 | `get_rule_statistics` | 7 | **4** | 3 | 规则/用量/匹配三类各自合并；`high_usage_rules`（top-N 列表）保留独立查询 |
| R24-3 | `get_alert_stats` | 4 | **2** | 2 | total/unread/today → 1；`by_severity` group_by 保留 |
| R24-4 | `get_audit_stats` | 6 | **4** | 2 | total/last_24h/last_7d → 1；severity/type/top_ips 保留 |
| R24-5 | `get_dashboard_data` | 4 | **2** | 2 | 今日/近7日/近7日正向 → 1；`category_stats` group_by 保留（缓存 warmup 内 flush） |

### R24-7 回退（composite_score_service.get_student_composite_score）

- **改动**：将「取分 + 排名」合并为单条带相关子查询的语句（`db.session.query(CompositeScore, rank_subq)`，排名按 `composite_score` 严格大于计数 +1）。
- **暴露的回归**：全量回归出现唯一失败 `test_composite_score_service::test_get_student_composite_score`（`assert None is not None`）。
- **根因**：该测试为 **mock 单测**，桩的是原始双查序列 `CompositeScore.query.filter_by().first()`（取分）+ `CompositeScore.query.filter().count()`（排名=0+1）。合并后代码改走 `db.session.query(...)`，mock 不再命中该路径 → 无行 → 返回 None。逻辑对**真实库正确**（R24 数值用例曾通过），但与 mock 结构强耦合。
- **处置**：按战役铁律「破坏既存测试的提取宁可跳过不强推」，且该处仅省 1 查、收益边际，执行 `git checkout HEAD -- composite_score_service.py` **字节级还原**（含原始 import 与 EOL）。`git diff HEAD` 复核为空 diff。
- **测试联动**：`tests/test_r24_aggregation.py` 删除 `TestR24CompositeScore` 类（18→15 用例），并清理随之无用的 `CompositeScore` / `CompositeScoreService` import、更新 docstring。
