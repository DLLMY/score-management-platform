## 三、逐函数技术甄别（可机械提取项 vs 需拍板核心）

> 判定标准：纯「整块搬到单 helper、签名不变、调用点不变」= 逐字节等价，属 c901 skill 一阶手法，零语义改变。

### 1. `execute_subject_import` (37) —— 收益最大
- **可机械提取（零 DB）**：嵌套 `validate_item(item)`（310–333，纯规则 required/max_length/min_length/regex 校验）→ 提为模块级 `_validate_subject_import_item(item, rules)`。
- **可机械提取（只读查询）**：嵌套 `resolve_relations(item)`（335–416，班级/教师解析+角色校验）→ 提为模块级 `_resolve_subject_import_relations(item)`；其内部可再拆 `_resolve_class_id(item)` / `_resolve_teacher_id(item)`（各 ~12）。
- 提取后主函数复杂度预计 **37 → ~20**。

### 2. `resolve_relations` (22)
- 纯机械拆 `_resolve_class_id` / `_resolve_teacher_id`（各含空/格式/长度/存在性校验 + 角色校验）→ 各 ~12。逐字节等价。

### 3. `import_devices` (31)
- **可机械提取（只读查询）**：循环内长 if/elif 校验链（设备ID/名称/班级/管理员 各自的空/格式/长度/存在性/角色校验，176–261）→ 提为 `_validate_device_import_row(row_dict, device_map, class_map, admin_map)`，返回 `(row_errors, parsed)`。
- 提取后主函数复杂度预计 **31 → ~15**。

### 4. `execute_score_import` (11)
- 收益小（已 11）：可提 `_locate_score_columns(headers)` 与 `_parse_score_row(...)`（列定位 + 单行解析 upsert 准备）。提后 ~8。
