- 日期：2026-09-14
- 目标：把散落在各模块的 `os.getenv` / `os.environ.get` 配置读取收敛到「单一 Config 类」。
- 结论：**主体目标已达成**，剩余散落读取均属「有意保留」，不并入 Config 不违反本任务目标。

## 三、逐类「有意保留」理由（为何不强行合并）

### 1. `security_config.py` — 默认值语义分歧（安全红线）
- `CORS_ORIGINS` 默认 `"*"`（`security_config.py:13`），而 `config.py:228` 默认 `"http://localhost:3000,http://127.0.0.1:3000"`。
- `RATE_LIMIT_PER_MINUTE/HOUR` 默认 `"30"/"1000"`，与 `config.py:221-222` 数值**一致**，但 `config.py` 在 `FLASK_ENV=="development"` 时**会放宽到 200/5000**（`config.py:224-226`）。
- 若并入 Config：开发环境会拿到放宽值而非原始 30，且 CORS 默认会从 `"*"` 变成具体 origin。属「改线上默认值」，违反铁律，**保留原 `os.getenv`**。

### 2. `security.py` — fallback 链分歧
- `JWT_SECRET_KEY = os.getenv("JWT_SECRET_KEY", os.getenv("FLASK_SECRET_KEY"))`（`security.py:20`）。
- `config.py:210` 的 fallback 是 `_generate_secret_key()`（每次随机）。
- 合并会改变「未设 JWT_SECRET_KEY 时」的兜底密钥来源，破坏既有签名兼容，**保留**。

### 3. `rate_limit.py` — 动态键 + 环境判断
- `os.getenv(f"RATE_LIMIT_{limit_name.upper()}")`，键名在运行时按 `limit_name` 动态拼装（`rate_limit.py:19`）。
- `Config` 仅暴露固定属性（`RATE_LIMIT_PER_MINUTE` 等），无「任意 RATE_LIMIT_*」通用读取。强行合并需重构为固定属性，会丢失动态 limit 名能力，**保留**。

### 4. `permission.py` — 防御性解析
- `int(os.getenv("PERMISSION_CACHE_TTL", "30"))` 包在 `try/except (TypeError, ValueError)` 内（`permission.py:313-316`），目的是 env 配了非数字时回落 30 而非崩溃。
- 若上移到 `Config` 初始化，解析失败会从「运行时兜底」变成「app 启动即崩」，改变错误时机，**保留原写法**。

### 5. `ota_negotiation_service.py` — 专用特性开关 + import 副作用
- 12 处 `OTA_*` 模块级常量，带 `int()` 的 `try/except` 防御解析，语义上是「按环境可调的 OTA 特性开关」。
- `Config` 类未注册这些键。若在 `Config` 注册并让 ota 模块 import 时调 `config_loader.get_config(...)`，会：
  - 把 `Config()` 实例化提前到 ota 模块 import 期，可能触发循环导入；
  - 把 `int()` 解析从运行时兜底移到 app 启动期。
- 该模块内聚读取 env 已是合理模式，**保留**。

### 6. 启动边界（§二 B 类）
- `config_init.py` / `run.py` / `wsgi.py` / `startup/run.py` / `app/__init__.py` 读取的是 `FLASK_HOST/PORT/ENV/LIGHTWEIGHT/START_CELERY` 等**进程启动参数**，执行时机早于或等于 `Config` 实例创建。改走 `ConfigLoader` 会造成「鸡生蛋」，**保留**。

## 四、判定

- **#196 实质达成**：核心基础设施配置已统一收敛到 `config.py::Config` 并通过 `config/config_loader.py::ConfigLoader` 单例对外暴露，主链路（MQTT/Redis/Celery/通知/限流）均已使用。
- **残留散落读取为有意保留**：每一处均有明确技术理由（真相源自身 / 启动边界 / 默认值语义分歧 / 动态键 / 防御性解析 / 专用特性开关），强行合并会违反「统一命名 ≠ 改线上取值」铁律或引入启动期风险。
- 若后续确有需求把 CORS/JWT/OTA/限流 等也强制统一到 Config（从而**改变线上默认值或启动期解析行为**），属更高阶决策，需单列授权 + 强杀重启 + 零回归闸门（pytest / run_regression），不在本次 #196 范围。
