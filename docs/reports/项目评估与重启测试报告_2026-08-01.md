## 6. 发现的问题与风险

### P1（建议优先处理）
1. **遗留进程占用 5000 端口**：`netstat` 显示 PID 6140 监听 127.0.0.1:5000，但 `taskkill` / `wmic` / `Stop-Process` / CIM `Terminate` 均无法终止（疑似运行于其他会话/容器/服务上下文，当前工具无权限）。本次被迫用 5001 启动新后端。建议用户在具备足够权限的会话中排查并结束该进程，或确认其来源。
2. **README 文档过时**：项目结构仍描述旧的 `backend/routes/`、`backend/app.py`（根目录）；前端语言写 JSX，实际为 TypeScript。与当前架构不符，易误导协作者。
3. **functional_test.py 路径失配**：脚本假设 `/api/dashboard`、`/api/system` 及某 swagger 解析方式，与真实 `/api/dashboard/data`、`/api/system/health`、`/api/swagger.json` 不符，导致误报失败。

### P2
4. **前端代理配置歧义**：运行时代理由 `src/setupProxy.js` 的 `REACT_APP_API_URL` 控制（默认 5000），`package.json` 的 `proxy` 字段被覆盖、实际无效，文档与行为不一致。
5. **后端启动重依赖**：首次启动需加载 BERT 权重并连接外部 MQTT（EMQX），耗时长（30s+）且 MQTT 连接失败会阻塞/重试，影响本地开发与可移植性。建议模型懒加载、MQTT 连接失败降级处理。
6. **默认弱口令**：管理员 `admin/123456`，README 已提示，部署前务必强制改密。
