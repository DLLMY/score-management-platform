## 2. 修复方案（R23-1）

| # | 位置 | 旧逻辑（重复查询） | 新逻辑 | 省查询 |
|---|---|---|---|---|
| C1 | `utils/permission.py::get_current_admin` | 每次调用查 1 次 `Admin`（路由层 + service 层同请求各查 1 次）→ **2** | `flask.g._r23_cached_current_admin` 请求级缓存，命中即返回 → **1** | 1/请求 |
| C2 | `utils/permission.py::get_allowed_classes` | 每次调用 3 次 SELECT（admin / admin_class / class_info），同请求内重复计算 → **3×调用数** | `flask.g._r23_allowed_classes_cache` 字典按 admin_id 缓存，同请求只算一次 → **3**（首调用） | 2/请求（二次起 0） |
| C3 | `services/operation_log_service.py::get_stats` | 5 条独立 `COUNT(*)` + by_type + by_day = **7** 次 `operation_log` 查询 | 5 指标合并为 1 条 `with_entities(func.count, func.sum(case...))` 条件聚合，by_type/by_day 不变 → **3** | 4 |
| C4 | `api/monitoring/operation_logs_routes.py::/summary` | 今日 3×COUNT + 本周 1×COUNT = **4** 次 `operation_log` 查询 | 今日 3 指标合并为 1 条条件聚合 + 本周 1×COUNT = **2** | 2 |

**关键设计**：

- C1/C2 的缓存**严格绑定 `flask.g`（请求级）**，不跨请求、不跨用户（`get_current_admin` 用哨兵 `_CURRENT_ADMIN_MISSING` 区分"未缓存"与"查无此人"）；并对 `RuntimeError`（无 request 上下文的单元测试）做防御性降级，返回 `None`/不缓存，与生产"路由层必带上下文"契约一致，caller 均已做 None 守卫。
- C3/C4 复用 R22 同款 `func.sum(case((ilike(...),1), else_=0))` 条件聚合写法；`by_type`/`by_day` 与 `/summary` 响应 JSON 结构**逐字节不变**（仅内部实现由多 COUNT 收敛）。

EOL 守恒（逐字节核验）：`permission.py`=LF、`operation_log_service.py`=LF、`operation_logs_routes.py`=CRLF(138)、`test_operation_log_routes.py`=LF、`test_permission_utils.py`=CRLF(354)。
