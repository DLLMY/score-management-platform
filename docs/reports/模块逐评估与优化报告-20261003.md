### 6.2 ⚠️ 关键回归教训（算法装饰器复用）

初版 `algo_safe_handle = partial(safe_handle, default_status=400, message="...")` **误用导致整个 api 包 import 崩溃**：`safe_handle` 是装饰器**工厂**（首参为 `default_status`，并非 `func`），`@algo_safe_handle` 裸调用会把路由函数作为首个**位置参数**填入 `default_status` 槽位 → `TypeError: safe_handle() got multiple values for argument 'default_status'`。该异常被 conftest 的 `walk_packages` 捕获并吞掉 → `_API_MODULE_NAMES=[]` → **所有命名空间 0 注册 → 全部路由测试 404（49 失败假象）**。

**正确写法**（已落地）：用闭包显式接收 `func` 再转发工厂——
```python
def algo_safe_handle(func):
    return safe_handle(default_status=400, message="算法计算失败，请稍后重试")(func)
```
修复后 `walk_packages` 全 114 模块导入成功、针对性测试 **168 passed / 0 failed**，印证"装饰器工厂不可用 partial 占位"这一易错点。
