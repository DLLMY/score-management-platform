## 🏗️ 架构概述

### 分层架构设计

系统采用三层架构设计，职责边界清晰：

```
┌─────────────────────────────────────────────────────────────┐
│                        API层 (routes)                       │
│  处理HTTP请求、参数验证、响应封装、权限检查                   │
└────────────────────────────┬────────────────────────────────┘
                             │
┌────────────────────────────▼────────────────────────────────┐
│                        服务层 (services)                    │
│  业务逻辑处理、数据库操作封装、缓存管理、第三方服务调用        │
│  31个服务类，通过DI容器统一管理                              │
└────────────────────────────┬────────────────────────────────┘
                             │
┌────────────────────────────▼────────────────────────────────┐
│                        模型层 (models)                      │
│  数据库模型定义、数据访问层、SQLAlchemy ORM                  │
└─────────────────────────────────────────────────────────────┘
```

### 服务层服务列表

| 服务名称 | 说明 |
|---------|------|
| notification_service | 通知服务 |
| cache_service | 缓存服务 |
| redis_cache_service | Redis缓存服务 |
| alert_service | 告警服务 |
| export_service | 导出服务 |
| system_config_service | 系统配置服务 |
| score_rule_service | 积分规则服务 |
| mqtt_message_service | MQTT消息服务 |
| mqtt_management_service | MQTT管理服务 |
| nlp_service | NLP服务 |
| anomaly_service | 异常检测服务 |
| prediction_service | 预测服务 |

### 核心技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| 后端框架 | Flask + Flask-RESTX | RESTful API框架，自动生成Swagger文档 |
| 数据库 | SQLite / PostgreSQL | 轻量级数据库，支持迁移到PostgreSQL |
| 缓存 | Redis | 分布式缓存，支持连接池管理 |
| 消息队列 | MQTT | 设备通信协议 |
| 异步任务 | Celery | 异步任务处理（导出、数据同步） |
| 依赖注入 | dependency-injector | 统一服务管理 |
| 部署 | Gunicorn + gevent | 生产环境WSGI服务器 |

## ⚙️ 服务管理

### 启动顺序

1. **后端服务** (端口 5000)
   - 启动命令：`cd backend && python app.py`
   - 状态检查：http://localhost:5000/api/docs/

2. **前端服务** (端口 3000)
   - 启动命令：`cd frontend && npm start`
   - 状态检查：http://localhost:3000

3. **ngrok内网穿透** (端口 4040)
   - 启动命令：`cd deploy\ngrok && ngrok.exe http 3000`
   - 管理面板：http://localhost:4040

### 自恢复功能

服务管理器 (`service_manager.py`) 具有以下功能：

- ✅ 自动监控服务状态
- ✅ 服务异常时自动重启（最多5次）
- ✅ 启动前自动清理已有进程
- ✅ 详细的日志记录
- ✅ 支持Ctrl+C优雅停止

## 🔄 配置热更新

系统支持配置文件变更的自动检测和重新加载，无需重启服务。

### 功能说明

- **监控文件**: `config/config_loader.py` 管理的所有配置文件
- **检查间隔**: 30秒（可配置）
- **自动重新加载**: 检测到文件变更时自动重新加载配置实例

### 配置方式

在 `service_init.py` 中启动配置监控线程：

```python
from config.config_loader import config_loader

# 启动配置监控线程（默认30秒间隔）
config_loader.start_config_watcher()

# 自定义检查间隔
config_loader.start_config_watcher(interval=60)
```

### 使用示例

```python
from config.config_loader import config_loader

# 获取配置（自动使用最新配置）
broker = config_loader.get_config('MQTT_BROKER')
port = config_loader.get_config('MQTT_PORT')

# 专项配置获取
mqtt_config = config_loader.get_mqtt_config()
redis_config = config_loader.get_redis_config()
```

## ⚙️ Gunicorn配置

生产环境推荐使用Gunicorn作为WSGI服务器，支持多进程和协程模式。

### 配置文件

**文件路径**: `backend/gunicorn_config.py`

### 核心配置参数

| 参数 | 说明 | 默认值 |
|------|------|-------|
| bind | 绑定地址和端口 | `0.0.0.0:5000` |
| workers | 工作进程数 | `4` |
| threads | 每个工作进程的线程数 | `2` |
| worker_class | 工作模式 | `gevent` |
| timeout | 请求超时时间(秒) | `120` |
| graceful_timeout | 优雅重启超时(秒) | `30` |
| max_requests | 最大请求数 | `1000` |

### 启动方式

```bash
# 使用Gunicorn启动
gunicorn -c gunicorn_config.py app:app

# 或使用PowerShell脚本
.\start_backend.ps1
```

### 配置来源

配置参数从 `config.py` 读取：

```python
# config.py
GUNICORN_BIND = '0.0.0.0:5000'
GUNICORN_WORKERS = 4
GUNICORN_WORKER_CLASS = 'gevent'
GUNICORN_TIMEOUT = 120
```

## 🧩 依赖注入容器

系统使用 `dependency-injector` 库实现依赖注入，统一管理服务实例。

### 容器配置

**文件路径**: `backend/di/__init__.py`

### 服务注册

服务通过 `DIContainer` 类注册：

```python
class DIContainer(containers.DeclarativeContainer):
    config = providers.Configuration()

    notification_service = providers.Singleton(
        'services.notification_service.NotificationService'
    )

    system_config_service = providers.Singleton(
        'services.system_config_service.SystemConfigService'
    )

    score_rule_service = providers.Singleton(
        'services.score_rule_service.ScoreRuleService'
    )

    # ... 共31个服务
```

### 使用方式

```python
from di import DIContainer

# 初始化容器（应用启动时自动完成）
container = DIContainer()
container.init_resources()

# 获取服务实例
config_service = container.system_config_service()
rule_service = container.score_rule_service()
```

## 🔍 故障排查

### 问题1：端口被占用

```
Error: Port 3000 is already in use
```

**解决方案**：
```cmd
# 查找占用端口的进程
netstat -ano | findstr ":3000"

# 结束进程（将PID替换为实际进程ID）
taskkill /PID <PID> /F
```

### 问题2：ngrok连接失败

```
ERR_NGROK_8012: Connection refused
```

**解决方案**：
1. 确保前端服务已启动（http://localhost:3000）
2. 重启ngrok：
   ```cmd
   cd deploy\ngrok
   ngrok.exe http 3000
   ```

### 问题3：登录失败（外网访问）

**症状**：本地登录正常，外网访问登录失败

**解决方案**：
1. 确保 `.env` 文件中 `REACT_APP_API_URL=` 为空
2. 重启前端服务：
   ```cmd
   cd frontend
   npm start
   ```

### 问题4：npm install 失败

**解决方案**：
```cmd
# 清理npm缓存
npm cache clean --force

# 删除node_modules
rd /s /q frontend\node_modules

# 重新安装
cd frontend
npm install
```
