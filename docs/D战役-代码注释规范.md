# D 战役 · 代码注释与文档字符串规范（L1）

> 目标：在不破坏既有代码的前提下，统一注释风格、提升可读性、让新代码可维护。
> 模板参考：`apps/backend/utils/decorators.py`（模块 docstring 范式）。

## 1. 模块（文件）docstring 范式

每个有公共 API 的模块顶部写模块 docstring，结构：**一句话定位 + 设计要点 + 用法示例**。

```python
"""路由层统一异常处理装饰器（B4 公共逻辑提取 2026-08-22）。

收敛各路由重复的 `try/except → APIResponse.error` 样板。把未捕获异常统一转成标准错误信封，
避免异常逃逸导致返回非信封格式（破坏前端 envelope 解析）或裸 500。

设计要点：
- 透传 werkzeug HTTPException（401/403/404 等），交给 Flask 既有错误处理器；
- 业务自定义异常若带 code/status_code/message 属性则透传，否则用默认 500 信封；
- 仅包装「真实异常」，正常返回路径零侵入。

用法：
    from utils.decorators import safe_handle
    class XResource(Resource):
        @safe_handle()
        def get(self): ...
"""
```

要点：
- 第一行一句话说明"是什么 + 何时引入/归属战役"。
- `设计要点` 列出非显然的决策与坑（锁、兼容、零侵入）。
- `用法` 给最小可运行示例。

## 2. 函数 / 方法 docstring

- 公共函数、非平凡逻辑、含隐含契约的参数必须写 docstring。
- 至少说明：做什么、关键参数语义、返回值、以及**与既有行为的兼容约束**。
- 例（`safe_handle` 源码 line 33）：明确列出 `default_status` / `message` / `error_code` 三参数的取值约定与向后兼容含义。

## 3. 行内注释

- 标注**为什么**（非显而易见的原因），而非复述代码。
- 涉及"铁律/坑"处加中文注释锚定（如"后端源码是唯一事实来源""统一命名 ≠ 改线上取值"）。
- 避免大段注释掉的无用代码；确需保留说明用 docstring 或写明原因。

## 4. 命名与字面量

- 枚举/常量常量化（收拢字面量，**不跨语义合并**）：仅把相同语义的散落字面量收为常量，下游按字面量匹配的旧值原样保留。
- 收紧判据必须留兼容兜底（如在线判定 `is_device_online(d) or d.status=="online"`），注释说明兼容原因。

## 5. 可选静态检查（渐进启用，勿一次性强开）

- `ruff` 的 `D` 系列（pydocstyle）可逐步引入：`D100/D101`（模块/公开类缺 docstring）、`D102/D103`（函数/方法）、`D200/D205`（格式）。
- **现状**：仓库基线存在大量缺 docstring 的既有代码，一次性强开 `D` 规则会产生海量 violation。建议：
  1. 新代码默认写 docstring（本规范第 1–2 节）。
  2. 选择性对新增模块启用；既有代码按战役小批量补齐，不追求单 PR 清零。
- 既有被允许的 ruff 偏差（`BLE001`/`DTZ005`/`I001`/`LOG015`/`G201`/`TRY203` 等）维持不动，新增文件零新增。

## 6. 自查清单

1. 公共模块有"定位 + 设计要点 + 用法"三段式 docstring。
2. 非平凡函数说明了关键参数与兼容约束。
3. 行内注释解释"为什么"，不冗余复述。
4. 常量收拢不跨语义合并；收紧判据留兼容兜底并注释。
5. 不引入新的 ruff 基线偏差；中文路径/编码相关操作注释说明。
