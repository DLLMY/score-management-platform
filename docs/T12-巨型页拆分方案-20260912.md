## 1. 现状与判据

### 1.1 混合形态

前端页面为混合形态（实测 384 个 TS/TSX 文件）：

| 形态 | 数量 | 说明 |
| --- | --- | --- |
| `pages/Xxx.tsx` + `pages/xxx/` 目录 | 40 组 | **已确立的「装配层 + 实现目录」范式** |
| 仅 `pages/Xxx.tsx` 单文件 | 10 个 | 均 < 400 行（NotFound 44 / StudentLogin 130 … SystemMetrics 375） |
| 仅 `pages/xxx/` 目录（无入口文件） | 若干 | 由同级单文件壳导入 |

### 1.2 已确立的拆分范式（第一轮已完成）

```tsx
// pages/SubjectManagement.tsx —— 装配层，13 行
import { SubjectManagementView } from './subjectManagement/SubjectManagementSections';
import { useSubjectManagementLogic } from './subjectManagement/useSubjectManagementLogic';

function SubjectManagementPage() {
  const props = useSubjectManagementLogic();
  return <SubjectManagementView {...props} />;
}
```

即「**hook（全部 state/effect/handler/列定义） → View（纯展示） → 入口壳（props 装配）**」三层已就位。
`scoreEntry` / `courseSchedule` / `userList` 入口壳仅 18 / 18 / 39 行，说明**第一轮逻辑外提已彻底完成**。

### 1.3 本轮判据：**单文件行数**，而非目录总行数

目录总行数大（如 `algorithm-analysis/` 4583 行）属**功能体量本身**（12 个 Tab），不是拆分缺陷；
真正的问题是 **单个文件超过可维护阈值**。以 600 行为线，`pages/` 下 24 个文件超标。

## 3. 拆分范式（在既有范式上补二级规则）

```
pages/<page>/
  types.ts                 # 共享类型（搬移须保持 export）
  constants.tsx            # 色板/映射表/预设（如 CLUSTER_COLORS、presetColors、defaultForm）
  helpers.tsx              # 纯函数渲染块（如 renderScoreDistribution）
  use<Page>Logic.ts[x]     # 主逻辑 hook —— 仅做「子 hook 组合 + 跨域协调」
  hooks/                   # 【新增】页内私有子 hook
    use<Page><Domain>.ts
  components/              # 【新增】页内私有展示组件
    <Domain>Panel.tsx
    <Domain>Grid.tsx
  <Page>View.tsx           # 编排：只做布局与 props 透传
  <Page>Sections.tsx       # 兼容层（如被入口壳引用，保留 re-export 或直接改壳）
```

**三条硬规则**（沿用项目既有约定，不引入新风格）：

1. **入口壳路径不变**：`App.tsx` 用 `import('./pages/Xxx')` 懒加载，`pages/Xxx.tsx` 必须继续可解析 → 目录新增 `index.ts` 时须与壳同源，禁止改动 `App.tsx`。
2. **导入走 barrel**：新增 `hooks/`、`components/` 子目录必须建 `index.ts` 并在页内聚合；跨页复用的沉到 `src/hooks` / `src/components` 根 barrel。
3. **类型与常量随实现搬迁**：`types.ts` 里的 `interface`/`const` 被搬走时**必须 `export`**（否则页内其它文件引用断裂）。

### 3.1 拆法 A —— 展示组件按 Panel 切（**最低风险，先做**）

适用：`analysis/AnalysisSections.tsx`（已含 9 个 Panel）、`scoreAnalysis/ScoreAnalysisSections.tsx`、`opsCenter/OpsCenterView.tsx`、`dashboard/DashboardView.tsx`。

```
AnalysisSections.tsx (727)  →  components/BasicStatsGrid.tsx
                              components/AlgorithmInsightCards.tsx
                              components/ScoreDistributionPanel.tsx
                              components/ClusterDistributionPanel.tsx
                              components/RiskWarningPanel.tsx
                              components/TopUsersRanking.tsx
                              components/ScoreTrendPanel.tsx
                              components/CorrelationPanel.tsx
                              components/NeedAttentionPanel.tsx
                              constants.tsx   (CLUSTER_COLORS / RISK_COLORS / getClusterColor)
                              types.ts        (9 个 interface)
```
每个 Panel 是**自包含纯组件**（props 进、JSX 出），无共享闭包 → 搬迁零风险。

### 3.2 拆法 B —— 巨型 View 按区块切

适用：`CourseScheduleView`(867)、`SubjectManagementView`(865)、`PermissionManagementView`(948)、`RuleView`(749)、`MentalHealthView`(711)、`CommitteeListView`(614)。

手段：按视觉区块（筛选栏 / 概览卡 / 主表格 / 侧栏 / 弹窗）切出子组件，View 退化为**布局编排**。
风险点：闭包内共享的局部 state 需**上提或经 props 下传** → 每切一个区块必须 `tsc` 兜住类型。

### 3.3 拆法 C —— god hook 按域切（**风险最高，最后做**）

适用：`useNLPManagementLogic`(1005)、`useScoreEntryLogic`(1055)、`useUserListLogic`(893)、`useDeviceManagementLogic`(830)、`useAlgorithmAnalysisLogic`(808)。

```
useNLPManagementLogic.ts (1005, 42×useState)
  → hooks/useNLPParse.ts        (句法解析域)
    hooks/useNLPRules.ts        (规则域)
    hooks/useNLPTraining.ts     (训练域)
    hooks/useNLPStatistics.ts   (统计域)
    hooks/useNLPCorrections.ts  (纠错域)
    useNLPManagementLogic.ts    (组合 + 跨域协调，目标 < 250 行)
```
判定维度：**按 Tab / 按数据域 / 按视图模式**。切分边界须满足「子 hook 之间无双向依赖」，先画依赖图再动刀。

风险：`useEffect` 依赖数组、闭包捕获、渲染次数变化。保障：`eslint-plugin-react-hooks` 报错为零 + 页面级 vitest 保绿。

## 5. 每批闸门（缺一不可）

用 managed Node 22.22.2 直调二进制（**不要用 `node_modules/.bin/*`**）：

| 闸门 | 命令要点 | 通过标准 |
| --- | --- | --- |
| 类型 | `typescript/bin/tsc --noEmit` | 0 error |
| 规范 | `eslint/bin/eslint.js` | 0 error / 无新增 warning |
| 格式 | `bin-prettier.js --check` | 0 差异（printWidth 100 / singleQuote / semi / LF） |
| 测试 | `vitest/vitest.mjs run` | **38 文件 / 276 passed / 3 skipped**（不减） |

补充核查：
- 受影响页面的 `src/tests/components/<Page>.test.tsx` 必须保绿（`Analysis` / `OpsCenter` / `NLPManagement` / `ScoreEntry` / `UserList` / `RemoteNotify` / `Dashboard` / `StudentPortal` / `AlgorithmAnalysis` / `PermissionGuard` 等 15 个页面级测试）。
- 新增子目录必须有 `index.ts`，且**无循环 import**（`tsc` + eslint `import/no-cycle` 若启用则双保险）。
- 每个被搬走的 `interface`/`const` 必须是 `export`（否则 tsc 立刻报错，天然闸门）。

## 7. 验收标准

1. `pages/` 下**无单文件 > 600 行**（P0+P1 全清）；非 pages 域单列议题另议。
2. 页面目录内文件**平均 < 200 行**，最大 ≤ 400 行。
3. 四闸门全绿且 vitest 用例数不减（276 passed / 3 skipped）。
4. 每个新增子目录有 `index.ts`；无 `any` 新增；无 `!` 非空断言批量绕过。
5. 全程 `App.tsx` 路由 import 路径零改动。
