## 四、数据流转与正确性核验

### 4.1 鉴权 / 信封一致性
- 全部写/读端点均挂 `@requires_permission(...)`；未登录返回 **401**（非 404），证明路由已注册但需鉴权。
- `api_versioning.py` 已注册统一错误信封，401/403/404 均输出 `{success:false, message, error_code}`，与前端 `getErrorMessage` 文案表对齐。

### 4.2 隐私隔离（班主任只能看本班）
四个无 `class_id` 字段、需经 `User` 关联的模块，隔离实现已逐行核验：

| 模块 | 隔离实现 | 越权返回 |
|------|---------|---------|
| `teacher_comment` | `list_comments` 合并单次 `join(User, User.id==TeacherComment.student_id)` 后 `filter(User.class_info_id.in_(allowed_ids))`；`get/update/delete` 经 `_ensure_access` | 403 |
| `study_guide`（改进计划） | `update_plan/delete_plan/update_plan_progress` 经 `_ensure_plan_access` 校验 `student.class_info_id in get_admin_class_ids(admin.id)` | 403 |
| `parent` | `list_contacts/get_contact/list_contact_logs` 合并单次 JOIN，跨班 `filter(False)` 或返回 403 | 403 / 空 |
| `mental_health` | `list_records/list_alerts` 合并单次 JOIN；`Alert.source=="mental"` 校验 | 403 / 空 |

> 关键点：隔离过滤与显式 `class_id` 过滤**合并为单次 join**，规避了此前 SQLite 多次 JOIN `user` 报 `ambiguous column` 的坑。

### 4.3 404 / 200 正确性
- 不存在的资源：`get_comment`/`update_plan`/`delete_plan` 等对 `query.get(id)` 为 `None` 时返回 `{success:false, message:"…不存在"}, 404` —— pytest 已覆盖。
- 创建类端点返回双元组 `[envelope, 201]`（如 `create_comment`、`create_plan`、`create_term`、`create_member`），符合 API 信封契约。
