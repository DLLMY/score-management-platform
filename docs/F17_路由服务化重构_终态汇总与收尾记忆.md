## 2. 防腐层范式与铁律（面向未来维护）

1. **写入 / 事务收口 service**：所有 `db.session.add/update/delete/commit/rollback` 在 `services/*_service.py` 内完成。
2. **路由薄壳保留项**：`get_or_404`（404 语义）、请求级校验、`invalidate_cache` / `invalidate_by_tag`、跨切面副作用（MQTT 下发 / `Notification` 落库 / `CompositeScoreService.recalculate_user_score` / `log_operation`）、响应构造。
3. **只读 GET 暂缓**：按评估「只读 `db.session.query` 可暂缓」，列表 / 详情 / 统计等只读路径未迁入 service（除非含可复用序列化）。
4. **契约零漂移**：响应体 / 状态码 / 错误信息逐字节不变；create 端点历史双元组 `[dict, 201]` 信封形态保留。
5. **每域 6 步范式**：快照基线 → 测试先行（迁移前补强行为断言锁契约）→ 建 service → 改写路由 → 全闸门 → 文档 / 记忆。
6. **禁止一次性 883 处全改**；**禁止 git commit**（须用户明确指示）。

## 3. 迁移中修复的生产缺陷（测试先行暴露）

| 域 | 缺陷 | 修复 |
|---|---|---|
| scores/records | score-entry `record.operation_log_id = log_operation(...)` 返回值被改（bool 而非 `OperationLog`）→ `AttributeError` 500；路由侧重复积分累加（service 累加一次、路由又改一次 → `new_score` 偏差 `2×change`） | 加 `hasattr` 守卫 + 删除路由侧积分改写，原子累加全交 service |
| monitoring/notifications | `Notification.query.filter_by(...).get_or_404(id)` 在 SA2.0 抛 `InvalidRequestError` → 详情/PUT/DELETE/标记已读 4 端点 500；`GET /user/<id>` 漏 `.paginate()` → 500 | 改 `filter_by(...).first_or_404()`；补 `.paginate(...)` |
| devices/firmware | upload 操作日志引用未定义 `sha256` → `NameError` 500；响应 `"md5": md5` 误用 `hashlib.md5` 模块对象 | 改 `md5_hex` 真值；响应取十六进制串 |

> 上述均为**写路径缺陷**，修复未改任何对外契约（成功响应结构 / 字段 / 状态码不变）。

## 6. #629 剩余写路径「全量收口」真终态闭合（2026-08-30）

> 背景：#610（2026-08-29）收口时，仍有少量**写路径 `db.session` 残留守卫**（rollback）/ 内联 commit 未被纳入，构成 #629。

### 6.1 批次落地（#976–#978）

| 批次 | 域 | 路由改动 | service 下沉点 |
|---|---|---|---|
