> 审查对象：`frontend/src`（56 页面 / 64 路由 / 11 个 Zustand store / 30+ hooks）。
> 方法：4 个子代理分维度静态扫描（数据流 / 状态调用链 / 操作路径 / 规范一致性）+ 主代理对关键疑点人工复核（grep/读码确认，排除误报）。基于上一轮「22 项问题修复」后的现状，聚焦**逻辑断点与设计偏差**。

## 0. 总体判断

**核心闭环完整度：约 85%**。主链路（登录→权限→导航→CRUD→反馈→空态）已闭环良好；**最大偏差集中在权限体系**（约 20 个在用权限码未注册，导致教师端成绩录入页核心按钮消失）与**零星数据流断点**（值日模块无数据源、若干保存后不刷新、分页/竞态防护缺口）。

## 1. 四维度审查结论

### 维度 A：数据流向闭环 — ⚠️ 6 处断点
- 🔴 **DutyRoster 值日任务无数据源**：`assignments`（DutyRoster.tsx:68）仅被创建/完成逻辑更新（:151/:166），**全文件无 fetch 初始化** → 首屏历史任务不可见、统计卡恒 0、删组不同步。
- 🟡 **DeviceManagement 保存设置不刷新**（:635-645）：更新设备名后无 `loadDevices()`，列表旧名等 10s 轮询才变。
- 🟡 **Notifications 删除/发送后 total 不同步**（:99-112）：本地 filter 不减 `pagination.total`；发送时后端缺 notification 字段则列表不更新。
- 🟡 **CultureBoard 班级筛选不联动**（:97-106）：`filteredRecords` 不过滤 `selectedClassId`，选班级列表不变。
- 🟡 **ExamManagement 拖拽排序失败不回滚**（:203-214）：本地顺序与后端永久不一致。
- 🟡 **跨页数据不同步**：DeviceManagement 绑定弹窗的 classes/admins 仅 mount 加载；ExamManagement/SubjectManagement 各自维护 subjects 无共享。

### 维度 B：状态管理与调用链 — ⚠️ 8 个死 store + 2 处隐性 bug
- 🔴 **11 个 store 中 8 个无消费者或只写不读**：`useUserStore`/`useDeviceStore`/`useScoreStore`/`useUIStore`/`useDashboardStore`/`useApprovalStore`（stores/index.ts:412/468/519/569/616/647 零消费者）；`useGlobalStore`（isOnline 无人渲染）、`useToastStore`（toasts 只写不读，实际渲染走 ToastContext）→ 状态管理双轨，新增功能易误用死 store。
- 🟡 **Dashboard 时钟冻结**（:307-312 + :876）：`currentTimeRef` 每秒更新但无 setState 驱动 → 页面时间永远不跳动。
- 🟡 **Dashboard 闭包过期**（:268-305）：useEffect 依赖 `[deviceStatuses]`/`[scoreUpdates]`，内部读旧 `state`；`stateRef`（:254）赋值后从未读取。
- 🟡 **useOptimisticUpdate 渲染期读 ref**（:163）：`pendingUpdates.current.length` 变更不触发重渲染，返回值陈旧。
- 🟢 **Sidebar 死 prop/字段**：`isMobileMenuOpen/onCloseMobileMenu`（App.tsx:251 未传）、`depth`、`requiresAdmin` 均无效；`PWAUpdateToast`（.js+.tsx 双实现零渲染）、`PreloadLink`/`withToast`/`AdvancedSearchFilter`/`OptimizedList` 等孤儿组件。

### 维度 C：操作路径闭环 — ⚠️ 3 处死路
- 🔴 **score.edit 未注册 → 成绩录入页对教师只读化**：ScoreEntry 主操作（批量/导入/保存/复制，:764/782/895/1062-1070）全用 `score.edit`，而 `config/permissions.ts:55-57` 仅注册 view/entry/approve → 有 `score.entry` 的教师进页面（App.tsx:335 放行）但**核心按钮永不渲染且无提示**。
- 🔴 **学生 401 跳转无 `#`**（api.ts:619 `window.location.replace('/student/login')`）：S2 修复遗漏分支，HashRouter 下落到服务器路径 → 404 而非学生登录页。
- 🟡 **ImportExportPanel 失败行只读死循环**（:693-747 + :333）：失败数据不可编辑，`handleReImport` 原样重提必然再失败；ClassManagement 导入失败后无重试出口。
- 🟡 **AttendanceManage「批量出勤/缺勤」实际仅记 1 条**（:169-177）：records 数组只含当前选中学生，按钮文案与行为不符。
- 🟡 **双身份并存**：Login/StudentLogin/登出均只清各自凭证（Login.tsx:90 / StudentPortal.tsx:141 / Sidebar.tsx:508），管理端可 URL 直达 `#/student`，隔离形同虚设。

### 维度 D：规范一致性 — ⚠️ 权限注册表脱节（最大偏差）
- 🔴 **约 20 个在用权限码未注册**：`score.edit`、`algorithm.manage`（AlgorithmAnalysis:1429）、`timetable.rule.manage`（ClassPeriodSettings:253）、`class.manage`/`student.manage`/`system.manage` 等 → PermissionManagement 无法授予、页面权限形同虚设（与 C 维度 score.edit 同一根因）。
- 🟡 **PhoneBoxPolicy 4 处 toast 参数颠倒**（:94/104/109/128）：`showToast('文案', 'success')` 反了 → 显示"success"文本 + info 样式，错误提示不可读。
- 🟡 **删除无确认 3 处**：ImportConfigManagement:173、RemoteNotify 模板:491、UserList 单条:579（批量有确认单条漏）。
- 🟡 **分页越界 2 处**：UserList:238、Notifications:104 删除末页最后一条后 page 未回退 → 空列表。
- 🟡 **竞态 2 处**：Notifications:44、ScoreEntry:248 快速切换筛选/班级时旧响应覆盖新结果。
- 🟡 **时间/数量极端值 3 处**：ExamManagement:298（start>end 不校验）、PhoneBoxPolicy:86（时段）、SeatingChart:92（rows/cols 放行 -5/9999）。
- 🟢 **窄屏溢出 2 处**：ScoreAnalysis:741 统计行、AttendanceManage:622 状态按钮 grid-cols-4。
- 🟢 **设计残留 3 处**：ScoreEntry:604 复制按钮"开发中"占位、Analysis:250 趋势无数据源、ScoreAnalysis:360 相关性无数据源（注释明示置空）。

## 3. 设计符合度总体结论

**符合良好（主流程）**：登录→权限门控→导航→列表/表单→toast 反馈→空态兜底全链路闭环；删除确认/提交防抖/危险操作确认覆盖率高；响应式表格滚动已全覆盖（上轮 L4）。

**不符合/偏差（需纠正）**：
1. **权限注册表与使用脱节（S1，最严重）**——设计上是"权限中心可分配"，实现上 20+ 权限码游离于注册表，权限控制形同虚设，且直接导致教师端成绩录入只读化。
2. **异常处理分支遗漏（S2）**——S2 修复只覆盖了 admin 401 主分支，学生 401 分支未覆盖。
3. **数据流断点（S3 + M3/M4/M5）**——值日模块缺数据源、若干保存/删除后不刷新，用户操作与界面事实不一致。
4. **状态管理双轨（M12）**——11 个 store 8 个异常，Global/Toast 双实现，违背"统一状态管理"设计。

**可信度评分：7.5 / 10（较上轮 6.5 提升）**——主流程闭环良好，剩余问题集中在权限注册表、学生 401 分支与值日数据源三处高风险点，修复成本低（多为 1-3 行改动）。
