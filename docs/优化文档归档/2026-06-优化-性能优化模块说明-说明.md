## 三、NLP服务模块

### 3.1 模块功能

提供统一的NLP解析服务入口，支持多种解析器切换，实现双层缓存机制（内存+Redis），通过轻量级解析器快速路径优化简单语句解析性能。

### 3.2 核心接口

#### `NLPService` 类

**初始化方法:**

```python
def initialize(self, parser_type: NLPParserType = NLPParserType.ENHANCED)
```

**解析方法:**

```python
def parse(self, text: str, parser_type: Optional[NLPParserType] = None) -> Dict[str, Any]
```

**返回结果结构:**

| 字段 | 类型 | 说明 |
|-----|------|------|
| success | bool | 解析是否成功 |
| intent | str | 意图类型（add/deduct/query/unknown） |
| name | str | 提取的姓名 |
| score | float | 提取的分数 |
| description | str | 操作描述 |
| confidence | float | 置信度（0-1） |
| cached | bool | 是否来自缓存 |
| cache_layer | str | 缓存层级（memory/redis/none） |
| parser_type | str | 使用的解析器类型 |

**缓存统计方法:**

```python
def get_stats(self) -> Dict[str, Any]
```

**返回字段:**

| 字段 | 类型 | 说明 |
|-----|------|------|
| cache_hits | int | 缓存命中次数 |
| cache_misses | int | 缓存未命中次数 |
| cache_hit_rate | str | 缓存命中率 |
| cache_size | int | 当前缓存大小 |
| cache_max_size | int | 最大缓存容量 |

**缓存管理方法:**

```python
def clear_cache(self)
def warmup(self, texts: Optional[List[str]] = None)
def async_warmup(self, texts: Optional[List[str]] = None)
```

## 十二、故障处理

### 12.1 Redis连接失败

**自动降级:** 当Redis连接失败时，系统自动切换到内存缓存模式。

**处理流程:**

1. 尝试连接Redis（最多3次重试）
2. 如果连接失败，初始化内存缓存
3. 所有缓存操作透明切换到内存模式
4. 记录Redis错误日志

### 12.2 NLP解析器加载失败

**自动降级:** 当某个解析器加载失败时，系统继续使用其他可用解析器。

**处理流程:**

1. 尝试加载所有解析器
2. 记录加载失败的解析器
3. 使用可用解析器提供服务
4. 通过轻量级解析器保证基本功能可用

### 12.3 缓存一致性问题

**解决方案:**

- 使用标签化缓存失效机制
- 设置合理的TTL自动过期
- 在数据变更时主动失效相关缓存
- 定期清理过期缓存


**说明:** 浅比较props，性能优于deepMemo，适用于简单类型props

### 18.4 扩展方式

#### 添加新预加载策略

```typescript
class PreloadService {
  // 添加时间触发预加载
  preloadAfterDelay(route: string, delay: number): void {
    setTimeout(() => {
      this.preload(route);
    }, delay);
  }
  
  // 添加条件预加载
  preloadIfCondition(route: string, condition: () => boolean): void {
    if (condition()) {
      this.preload(route);
    }
  }
}
```

## 二十一、健康检查器模块

### 21.1 模块功能

提供系统健康检查功能，定期检查数据库、Redis、MQTT等核心服务状态，支持单个检查和批量检查，通过API端点暴露健康状态。

### 21.2 核心接口

#### `HealthChecker` 类

**初始化方法:**

```python
def __init__(self, app=None, db=None, redis_client=None, mqtt_service=None)
```

**参数:**
| 参数 | 类型 | 说明 |
|-----|------|------|
| app | Flask | Flask应用实例 |
| db | SQLAlchemy | 数据库实例 |
| redis_client | Redis | Redis客户端 |
| mqtt_service | MQTTManager | MQTT服务实例 |

**健康检查方法:**

| 方法 | 说明 | 返回 |
|-----|------|------|
| `check_database()` | 检查数据库连接 | `{status, message}` |
| `check_redis()` | 检查Redis连接 | `{status, message}` |
| `check_mqtt()` | 检查MQTT连接 | `{status, message}` |
| `check_disk_space()` | 检查磁盘空间 | `{status, message}` |
| `check_memory_usage()` | 检查内存使用 | `{status, message}` |
| `check_cpu_usage()` | 检查CPU使用 | `{status, message}` |
| `run_all_checks()` | 运行所有检查 | 完整检查结果 |

**注册方法:**

```python
def register_check(self, name, check_func, critical=True)
def register_endpoint(self, app)
```

**检查结果状态:**

| 状态 | 说明 |
|-----|------|
| `healthy` | 正常 |
| `unhealthy` | 异常 |
| `degraded` | 降级 |
| `critical` | 严重 |
| `unknown` | 未知 |

### 21.3 API端点

| 端点 | 方法 | 说明 |
|-----|------|------|
| `/api/health` | GET | 综合健康检查 |
| `/api/health/<check_name>` | GET | 单个服务健康检查 |
| `/health` | GET | 基础健康检查 |

### 21.4 使用示例

```python
from utils.diagnostics import HealthChecker

health_checker = HealthChecker(app=app, db=db, redis_client=redis_client)
health_checker.register_endpoint(app)

# 运行所有检查
results = health_checker.run_all_checks()

# 单个检查
db_status = health_checker.check_database()
```

### 21.5 扩展方式

#### 添加自定义检查

```python
health_checker.register_check(
    'custom_check',
    lambda: {'status': 'healthy', 'message': '自定义检查通过'},
    critical=False
)
```
