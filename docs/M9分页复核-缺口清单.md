# M9 分页复核 — 缺口清单（2026-09-02）

> 审查性质：**只读复核**，未改任何代码。结论供用户审核后决定是否实施。
> 铁律③：新增分页 = 契约变更（加 `page`/`per_page` 查询参数 + 返回信封由裸数组改为 `{items,total,page,per_page,pages}`），**须经用户审核确认**，且需同步前端调用方（否则前端按数组消费会断）。
> 已知背景：`backend/utils/pagination.py::get_pagination(default, max=200)` 已存在；T3(#969) 战役已对主流大表列表端点强制分页。本复核查 #969 遗漏项。

## 二、已确认无遗漏（对照）
主流大表列表均已分页：`/users/`、`/scores/records/`、`/scores/approvals/`、`/scores/rules/`、`/devices/`、`/devices/<id>/heartbeats`、`/notifications/`、`/operation-logs/`、`/exam/`、`/classes/`、`/classes/<id>/students`（子资源已覆盖）、`/subject/`、`/course-schedule/`、`/nlp/rules/`、`/security/*` 等。

## 三、可豁免（无增长风险，注明理由）
- **RBAC/权限枚举**：`/rbac/*`、`/role-permissions/`、`/users/sub-accounts/`、`/admins/`
- **配置/字典/枚举**：积分分类、通知模板、排名规则、时段规则、导入配置、科目班级关联、设备组选项、课程表选项等
- **导出/模板/备份全量**：所有 `/export`、`/template*`、`/backup/*`、`/reports/class-semester`（依赖鉴权，非 M9 对象）
- **受当前用户范围约束**：`/student/records|notifications|leaves`（`requires_student` 限定单人）
- **聚合/计算/表单选项**：`/analytics/*`、各 `*/statistics`、`/score-entry`、`/rules/templates`、各 `*/stats`、top-N、关键词约束类
- **单条/状态/内存**：`/<int:id>` 详情、`/me`、`/health`、`mqtt/logs`(内存)、`/recent`(后 50)、`phonebox-policy`

## 四、顺手统一建议（非硬缺口）
- `/api/devices/<id>/alerts`、`/api/firmware/ota-status` 硬编码 `limit(50)` 有界但信封非标准，可后续统一到 `get_pagination`。
- `/api/devices/advanced-stats` 对 `DeviceHeartbeat` 大表 `count()`，建议复核慢查询风险（性能层，非分页层）。

## 五、实施要点（待用户定夺范围）
1. **P0 必修**：`wol/devices`、`devices/online` 接 `get_pagination`，避免全表 dump。
2. **P1 批量修**：class_management 13 个 service 改 `get_pagination` 信封；排行榜 5 个 `limit` 改 `get_pagination(max=200)`。
3. **P2 可选**：轻量子资源统一（低收益，可暂缓）。
4. **契约同步**：每个加分页的端点，返回由 `[...]` 改为 `{items,total,page,per_page,pages}`，**前端对应调用方须同步改消费**（否则破窗）。实施时需一并改前端或列前端改动清单交用户审核。
5. **零回归闸门**：后端 `py_compile` + `bash scripts/run_regression.sh`；前端 `tsc --noEmit` + `eslint` + `vitest run`。
