## 事故：git 仓库损坏与恢复（D-M1 全量回归隔离时踩坑）
- 起因：为隔离 D-M1 是否引入回归，尝试 `git stash push -u` 暂存 7 个 D-M1 文件；该 python 子进程被沙箱 SIGTERM 打断。
- 后果：`git stash` 中断把 `.git/refs` 整个目录删掉 + `.git/objects/pack` 下 `.pack` 数据文件丢失（仅剩 `.idx`）+ 近期提交松散对象（45ef720/1f3d7ec 等前缀目录）消失 → git 报 `not a git repository` / `bad object HEAD`。
- 恢复：① 重建 `.git/refs/heads` 与 `refs/remotes/origin`；② 把 `refs/heads/main` 与 `refs/remotes/origin/main` 松引用写回真正本地 tip `45ef72009384398214a10969a8de713f1f4b78f4`（依据 `.git/logs/HEAD` 与 push 记录）；③ 删 orphan `.idx` 与 `multi-pack-index`；④ `git fetch origin`（M2/1f3d7ec、L2/45ef720 均已 push）重新拉回对象库 → 全恢复，`status` 精确显示 7 个 D-M1 改动。
- **铁律：本仓库禁止再通过被 shim 破坏的 bash 跑任何 git 写操作（stash/commit/reset）。git 命令一律用 `os.chdir(REPO)+subprocess.run(['git','--git-dir=.git','--work-tree=.',...])` 二进制直跑；commit/push 走专门的 `.py` 脚本。**
