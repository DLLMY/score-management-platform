### 关键经验（与 E6a hook 抽取的区别）
1. **props 集合用脚本枚举，别手数**：渲染段所有标识符 ∩ 逻辑段已声明名（含 `const {a,b}=` 与 `const [a,b]=` 两种解构，漏数组解构会少算 `isRefreshing` 之类）。
2. **早退分支归属**：`if (isLoading) return <X/>` / `if (error) return <Y/>` 属逻辑层，留在主文件（其 JSX 依赖的图标需留在主文件导入）→ UserDetail 有 2 个早退分支。
3. **columns 定义若留逻辑层，其 JSX 图标/Badge/formatXxx 需留在主文件导入**（FirmwareManagement 的 versionColumns 用了 Badge/PermissionButton/formatDateTime/lucide 图标）。
4. **`useForm`/`useListFetch` 的 props 类型不要用自造签名**，用 `UseFormResult<T>['setFormData']`、`ReturnType<typeof useListFetch<T>>`（实例化表达式在 TS5.9 可用），否则手写的 `(field,value)=>void` 与实际 `(Partial<T>|fn)=>void` 不匹配。
5. **同文件内联 interface 搬到 types.ts 必须加 `export`**（原同文件内使用无需导出）。
6. **切片易多带一个 `}`**：原组件是 `function X() { ... return (...); }`，切片末尾含 `}`；新 View 是箭头函数需 `};` → 生成后必查结尾是否出现 `}\n};`（本轮 3/4 页中招）。
7. **忠实度比对要分段**：页面含内联子组件时，`rfind('\n  return (')` 会取错起点（ScoreRecords 有 5 个 `  return (`）。须「子组件段」与「主渲染段」分别比对，且主渲染段要去掉 View 里新增的 `return (` 行。

- **忠实度：4 页渲染 JSX 逐行比对差异 = 0**（ScoreRecords 子组件段 266 行 + 主渲染段 47 行均 0 差异；其余 3 页 0 差异）。
