## 修复：幽灵资源残留（DELETE 404 不清缓存 → 反复删反复 404）

- **现象**：DELETE /api/subjects/11 404"请求的资源不存在"（科目 11 后端早已删除），但前端列表持续显示 11。后端列表（含缓存）ids=[8,9,4,6,3,5,1,2] 无 11。

## 系统性根治「幽灵资源/列表返旧」(缓存架构根因) + 全闸门验证（用户指令"彻底解决此类事件/继续完成任务"）

- **真根因（此前所有手动 invalidate 从未生效）**：`cached_api` 的 key 格式 `api:{path}:{sha256hash}`（**冒号**分隔）；而历史 invalidate pattern 形如 `api:/api/x/*`（**尾斜杠+星**）→ `x/` ≠ `x:` 前缀**永不匹配** → `cache.flush(pattern)` 永远删不到任何键。这才是删后反复 404 / 分配后不刷新 / 列表返旧反复出现的**总根源**（前端 404 清缓存、BYPASS、admin_classes 手动补 invalidate 都只是止血，根因在后端 pattern 错配）。

  3. `cached_api` BYPASS：`request.args.get("skip_cache")=="true"` 时跳过读写、X-Cache: BYPASS（早前已落）。
