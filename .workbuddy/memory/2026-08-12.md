## 设备删除 404 bug 修复
- 现象：DeviceManagement.tsx 点删除 → `DELETE /api/devices/SMOKE_E2E_001` 返回 404（同页 GET /api/devices、/stats、/alerts 均正常）。
- 根因：前端 `handleDeleteDevice(device.device_id)` 传设备**字符串业务标识**，后端 delete 路由 `@ns_devices.route("/<int:id>")` 仅接受整数主键 → 路径不匹配 Flask 直接 404，请求未进函数体。其余绑定/心跳接口用 device_id 字符串但后端对应路由接受字符串，故无问题。
- 修复：`frontend/src/pages/DeviceManagement.tsx` 删除按钮改传 `device.id`（数字主键），`handleDeleteDevice(id: number)` 用 `api.devices.delete(id)` 并按 `d.id` 过滤本地列表；与绑定班级/管理员的 `selectedDevice.id` 约定一致。
- 验证：前端 `vite build` 通过（4m29s，仅无害 CSS 拼写警告，无错误）；后端实跑「创建 id=11 → DELETE /api/devices/11 → 200 删除成功 → 删除后 GET 404」全链路通过。
- 提交：随本次提交推送（commit 见 git log）。
- 附：后端 admin 登录返回 `access_token` 在响应**顶层**（信封 `{success,code,data:{admin},access_token,refresh_token,...}`），不在 data 内；前端 `request` 拆信封后 login 类型签名 `Promise<{access_token,...}>` 与后端一致。
