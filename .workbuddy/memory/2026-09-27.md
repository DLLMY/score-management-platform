### 关键坑（B20 新增）
- **`__tests__/` 深一级 mock 路径**（B16/B19 同类坑第 3 次复发）：`pages/algorithm-analysis/__tests__/` 下必须写 `'../../../services/api'`，写成 `'../../services/api'` 会解析到不存在的 `src/pages/services/api` → mock 完全失效、**打出真实网络请求**。
- **依赖 mock 具名形参**：`vi.fn(() => socket)` 无参 → `mock.calls[0]` 被推断为空元组，`calls[0][0]` 报 **TS2493**；须写成 `vi.fn((_url?: string, _opts?: unknown) => socket)`。
- **`Record<string, unknown>` 承载 mock 方法会丢调用类型**：`mockSocket.emit.mockClear()` 报 TS18046；应在 `vi.hoisted` 里把 socket 声明显式对象类型（`emit: typeof emit`），而非 `Record<string, unknown>`。
- **`Array.prototype.at()` 不在本项目 tsconfig lib 目标内**：`.at(-1)` 报 TS2550 → 统一改 `.slice(-1)[0]`。
- **persist store 的 beforeEach `setState` 会回写 localStorage**：测「initTheme 跟随系统」前必须 `localStorage.removeItem('theme-storage')`，否则会走进「已有偏好」分支导致用例失效。
- **`setPermissions` 只改 store 状态，不写 localStorage**（持久化在 `fetchAndApply` 里）——断言别写到 localStorage 上。
- **`void get().fetchAndApply(id)` 是浮点 Promise**：断言 `getAdminRoles` 被调须用 `await vi.waitFor(...)`，不能只 `await` 外层调用。
- **`ReturnType<typeof vi.fn>` 不能直接赋给具体函数签名**（`Dispatch`/`showToast`）：声明 `type X = Deps['xxx']` 后 `vi.fn() as unknown as X`。
- **已存在 `stores/__tests__/stores.test.ts`**（202 行，覆盖 Permission/Toast/Global/Theme，**不含 WebSocketStore**）；本次新增 `index.test.ts` 与之部分重叠，但补全了 WebSocket 全部事件 handler 与 Permission 的缓存/重加载路径。**是否整合这两个文件留待用户决策**（未擅自改动既有文件）。
