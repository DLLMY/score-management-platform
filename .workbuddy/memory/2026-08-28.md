## P1-3 ✅ 前端信封契约统一 / 消除「假成功」（#927）

### 背景与根因
- `services/api.ts` 的 `unwrapEnvelope` 已是请求链的信封单一真相源（3 处调用点全在 `executeRequest`），**并非**重复实现。
- 真正的漂移面在**页面层**：5 个只读/展示型页面各自内联重写信封解析，其中 3 个是**逐字节相同**的 `fetchJson` 副本，另有 Diagnostics 4 处裸 `fetch`：
  - `SystemMetrics.tsx` / `SecurityAudit.tsx` / `OpsCenter.tsx`：三份完全相同的 `fetchJson<T>()`（含 `success===false → null` 的 M6 检查）
  - `FrontendTelemetry.tsx`：1 份 `fetchJson<T>()`，**缺 `success===false` 检查** → 真实假成功缺口（HTTP 200 + 业务失败被当数据渲染）
  - `Diagnostics.tsx`：4 处内联 `envelope?.data ?? envelope`，同样不判 `success`
- **排除的误报**（一度误判，已核实非 bug）：
  - `api.ts:5384` course-schedules `update` 的 `result.success` 复检 —— 后端 PUT 返回 `data:{success:true, message, schedule}`，`request()` 解包后 `result.success` 为真，逻辑成立。
  - `StudentPortal.tsx:125` `res.data`、`OperationLogs.tsx:62` `r.data ?? []` —— 均作用于**已解包载荷**的字段访问（`getNotifications` 返回 `{data,pagination}`、`operationLogs.getAll` 走 `request()` 已解包并抛错），非信封误用。

### 改动
1. `services/api.ts`：
   - `unwrapEnvelope` 加 `export`（原模块私有），函数体零改动。
   - 新增非抛出包装 `parseEnvelopeSafe<T>(rawData): T | null` —— try/catch 包 `unwrapEnvelope`，业务失败/异常归 `null`，无 `success` 字段的直出对象原样返回，供展示型页面复用同一契约。
2. 5 个页面收敛到 `parseEnvelopeSafe`，删除 4 份重复 `fetchJson` 实现（共 9 处解析点）：
   - `SystemMetrics` / `SecurityAudit` / `FrontendTelemetry`：`fetchJson` 体内联解析 → `return parseEnvelopeSafe<T>(env)`
   - `OpsCenter`：`fetchJson` 同改 + L246 内联 operation-logs 解析同改
   - `Diagnostics`：4 处 `envelope?.data ?? envelope` → `parseEnvelopeSafe<HealthData | PerformanceData | ErrorData | SystemData>(envelope)`
3. `services/__tests__/api.test.ts` 新增 9 例信封层直测（14 → 23）：
   - `unwrapEnvelope`（5）：成功取 data / `success:false` 抛 ApiError / `skipDataExtract` 原样返回 / 非信封直出不误吞 / 有 success 无 data 原样返回
   - `parseEnvelopeSafe`（4）：成功取 data / 业务失败返回 null 不抛 / `undefined|null` 归 null / 无 success 字段原样返回

### 收益
- 前端信封解析实现从 **5 份 → 1 份**（`unwrapEnvelope` 抛出版 + `parseEnvelopeSafe` 非抛出版）。
- 修复 `FrontendTelemetry`（1 处）与 `Diagnostics`（4 处）共 **5 处真实假成功**：此前 HTTP 200 + `success:false` 会把失败信封当数据渲染；现统一归 `null` 走空态/错误态。
- 页面 state 均为 `X | null`，返回 `null` 类型安全，成功路径行为不变。
