### 9.7 并发修复：MQTT 自循环（生产紧急，独立于本轮优化）
- **现象**：硬件端被灌入 `phonebox/unlock/A` 的重复开锁结果报文，`device_id=pbE2ETEST00001`（测试假 ID），`result:false / reason:card_not_found`。用户三假设（QoS1 重试风暴 / 硬编码测试 ID 重试循环 / 消费者卡住）均不成立。
- **根因（已确证）**：后端**控制连接既发布又订阅同一 topic 族** → 收到自己发出的下行结果 → 当作上行请求再发布 → 无限自循环。
  - `services/mqtt_manager.py:96` 控制连接订阅 `("phonebox/unlock/#", 1)`；
  - `mqtt_manager.py:1055` `publish()` 用同一控制客户端 `self._client` 发布下行结果到 `phonebox/unlock/A`；
  - `mqtt_manager.py:246-263` 控制 `on_message` 把 `phonebox/unlock/` 前缀派发到 `handle_unlock_message`；
  - `services/mqtt_message_service.py:276-278` `handle_unlock_message` 收到**无 card_id 的结果回环报文**时再次 `publish_unlock_result(...card_not_found...)` 到 `phonebox/unlock/A` → 自循环。
  - 一次任意 `card_not_found`（或任何）结果发布即可播种自循环（无需设备持续发请求）。`pbE2ETEST00001` 仅是首包入站 query 的 device_id 回声。
- **修复（零契约，已改 3 处）**：
