## #112 ④ 逐格推进收尾：**strict 整体开启** + noImplicitOverride

### 关键：先 CLI 逐 flag 量化，再决定是否「逐个堆叠」
在 #109/#110（noImplicitAny、strictNullChecks 已开）基础上，`tsc --noEmit --strict` 全量仅 **18 错误**。逐 flag 拆解：

| flag | 单独开启新增错误 |
|---|---|
| **strictFunctionTypes** | **18** |
| strictBindCallApply / strictPropertyInitialization / noImplicitThis / alwaysStrict / useUnknownInCatchVariables | **0**（全部） |

→ **推翻「逐个 flag 堆叠」的原计划**：代价 100% 集中在一格，18 处修完即可直接 `"strict": true`。

### 18 处的三个根因（全在类型声明层，零运行时变更）
1. **App.tsx 13 处（TS2322）**：`createLazyComponent(importFn: () => Promise<{default: React.ComponentType<unknown>}>)`
   —— 泛型参数位于 props **逆变位**，`unknown` 不能赋给页面的 `{}` props，故所有**显式标注 `React.FC` 的页面**全被拒。
   - **判据（可复用）**：报错集里「显式标注 `React.FC` 的页面全报错、无标注的 `function Xxx()` 不报错」→ 就是容器签名过严，而非页面有问题（后者参数更少，逆变下可兼容）。
   - 修法：`React.ComponentType`（默认泛型 `{}`）—— `React.FC` 恰好匹配，且**零 `any`**。
2. **codeSplitting.tsx 3 处（TS2352/TS2345）**：同型 `ComponentType<unknown>`。
   - 核实中发现该文件是 **181 行零消费者死文件**（8 个 export 全无引用、utils 无 barrel、无动态 import、无测试）→ **直接删除**，3 个错误随之消失。
3. **5 处函数参数逆变（TS2322）**：props 声明比真实实现**更宽**或**结构化类型不精确**
   - `approvals/types.ts`：`setSort: (field, order: string|null) => void`，而来源 `useTableUrlState` 给的是 `SortOrder`（`'ascend'|'descend'|null`）→ 收窄为 `SortOrder`。
   - `courseSchedule/types.ts`：`handleSubjectChange: (e: {target:{value:string}}) => void` / `handleFileChange: (e: {target:{files:FileList|null}}) => void`
     → 改 `ChangeEvent<HTMLSelectElement>` / `ChangeEvent<HTMLInputElement>`（与实现签名及 `<select>` / `<input type=file>` 真实 onChange 一致）。

### 顺手开启 noImplicitOverride（4 处，零 JS 产物差异）
`strict` 之外单独量化：**noImplicitOverride 4** / noUnusedLocals 13 / noUnusedParameters 7 / noUncheckedIndexedAccess **133** / exactOptionalPropertyTypes **157** / noPropertyAccessFromIndexSignature **187**。
- 4 处均为 class 覆盖 `React.Component` 成员（`lazy/LazyComponent.tsx` + `special/ErrorBoundary.tsx` 的 `componentDidCatch` / `render`）→ 补 `override`。纯编译期标注，**JS 产物零差异**。
- 后三项（133/157/187）**明确不推**：会迫使大量 `?? 0` / 断言补丁，**改变运行时语义**，风险远高于收益。
- noUnusedLocals/Parameters（13/7）与 eslint `no-unused-vars` 职责重叠（多为 `jsx: react-jsx` 下无用的 `import React`），另立批次评估。
