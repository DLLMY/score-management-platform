## 前端全量 vitest 沙箱 worker 崩溃坑（可复用，已二次踩+确诊）
- **根因（已确诊）**：两类崩溃同源——**全量并行 worker 上未清理的异步 error 事件（EventEmitter/定时器/网络 mock 遗留）冒泡到 worker 进程，触发 `Unhandled 'error' event` → `Worker exited unexpectedly`**。第一次 `--pool=forks`（默认 CPU 数并行）表现为 V8 堆 ~4GB `Mark-Compact ... allocation failure`；第三次 `--pool=threads --maxWorkers=2` 崩在 `getErrorMessage.test.ts` 之后且**无内存栈**——均非测试逻辑失败（同次 `Tests 259 passed`）。
- **关键验证**：`src/services/__tests__/getErrorMessage.test.ts` **单独跑 5 passed、exit 0 干净** → 证明崩溃不是文件自身缺陷，而是并行时序下前序文件泄漏的 error 事件在 worker 存活期冒泡。
- **判读**：这是**运行器基础设施/环境问题，非测试失败**；会导致 1 个测试文件因 worker 崩溃拿不到干净结果（35 passed + 1 skipped = 36，缺 1/37）。不能据此判绿或判红，必须重跑拿干净信号。
- **本版本 vitest 不支持** `--poolOptions` CLI（抛 `CACError: Unknown option`）；受支持的为 `--pool` / `--maxWorkers` / `--no-file-parallelism` / `--execArgv`。
- **正确重跑参数**（已验证规避）：**`--maxWorkers=1` 单 worker 顺序执行**（让每个文件 environment 独立 teardown、泄漏被清理，消除并行竞争）—— `NODE_OPTIONS="--max-old-space-size=8192" node node_modules/vitest/vitest.mjs run --pool=threads --maxWorkers=1 --reporter=dot`，managed Node 22.22.2。⚠️ `--maxWorkers=2` 仍崩，必须降到 1。
- 经验：沙箱类「段错误 / Worker exited / allocation failure」须先与真实测试失败区分；本例特征是"Tests N passed 但同时 1 error（Worker exited）"且退出码非 0。
