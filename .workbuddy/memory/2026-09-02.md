## CI vitest fork worker OOM 修复（优化收口）

- **现象**：GitHub Actions `ubuntu-latest` 跑 `npm test`（`vitest run`，默认 forks 池）全量 270 用例时，某 fork worker 撞 V8 旧生代堆上限（runner 上默认≈2GB）崩溃 → `FATAL ERROR: Ineffective mark-compacts near heap limit Allocation failed - JavaScript heap out of memory` → exit 1（35 文件 261 passed / 1 error）。
- **根因**：`frontend/vitest.config.ts` 设 `pool: process.env.CI ? 'forks' : 'threads'`；forks 池每个 worker 是独立 Node 进程，受 V8 默认堆上限约束；全量并发加载 antd/recharts 等重依赖时单 worker 易溢出（与本地沙箱 OOM 同源）。
- **修复**（`.github/workflows/ci.yml` 的 `frontend` job 加 job 级 `env`，双保险）：
  1. `NODE_OPTIONS: --max-old-space-size=4096` —— 抬高单 worker 堆上限（不影响测试逻辑/结果）。
  2. `VITEST_MAX_WORKERS: 2` —— 限制并发 worker 数，避免多核 runner 上堆峰值叠加打爆容器（vitest 原生支持，`coverage.*.js:380` 直接读 `process.env.VITEST_MAX_WORKERS`）。
- **校验**：ci.yml 结构回读无误（env 与 name/runs-on/steps 同缩进层级，job 级生效）；vitest 源码确认 `VITEST_MAX_WORKERS` 与 `config.maxWorkers` 受支持（无配置项名风险，优于改 `poolOptions`）。
- **已收口（本日推送完成）**：本地提交 `09ac50b`（ci.yml + 本日志）→ `git push origin main` 成功（`5da4546..09ac50b`），CI 已自动触发复跑。OOM 双保险（heap 4GB + maxWorkers 2）预期根治 forks 池崩溃。

## M10 useOptimisticUpdate 回滚边界修复（已实施 ✅）
- **缺陷**：`batchUpdate` 内所有 update 共享同一 `originalData`（批次初快照 S0），`rollbackUpdate` 把整个 `data` 恢复为 S0 → 批次部分失败时已成功的兄弟项被一并撤销。
- **方案甲（基准快照 + pending 派生预览）**：`useOptimisticUpdate.ts` 增 `baseDataRef`（事务初已提交快照）+ `appliedRef`（本事务内已应用更新序列）；`rollbackUpdate` 改为从 baseData 重放「除失败项外」所有已应用更新——单条/整批失败回退 S0（与原语义一致），批次部分失败仅撤失败项、保留成功项。事务边界（`performUpdate`/`batchUpdate` 当 data 存在时）重置两 ref，杜绝跨事务污染。
- **零回归闸门（前端，managed Node 22.22.2 全绿）**：`tsc --noEmit` OK；`eslint` 0 error；新增 `src/tests/hooks/useOptimisticUpdate.test.tsx`（3 用例：部分失败保留兄弟/单条失败整体回退/全成功不误回滚）`vitest run` 3 passed。
- 注：batchUpdate 对单项失败仅回滚、不 setError（error 仅用于整批抛错 catch），属既有设计，未改。

## CI OOM 三次根治（VITEST_MAX_WORKERS 2→1）
- **用户复跑仍 OOM**：推送 `c4224da`（分片 3 份）后 CI 复跑崩溃日志：`Test Files 11 passed | 1 skipped (13)`、`Tests 88 passed | 3 skipped (101)`、`Errors 1 error`、exit 1；`Worker forks emitted error` / `Worker exited unexpectedly` / `Allocation failed - JavaScript heap out of memory`；`Duration 449.78s`。
- **根因（非堆不够，是单 worker 重复加载重依赖）**：分片只把文件分散到 3 个 matrix runner，但 `VITEST_MAX_WORKERS: 2` 使**单 runner 内 2 个 fork worker 各自独立加载 antd/recharts** 一份 → 单 worker 旧生代堆涨到 ~4GB 撞 V8 上限 OOM。（CI 用 forks 池，Linux 下 threads 池报 `webidl.markAsUncloneable` 不可切 threads；本地 threads 池共享堆、重依赖仅加载一次故不 OOM。）
- **修复**（`.github/workflows/ci.yml` `frontend-test` job `env`）：`VITEST_MAX_WORKERS: 2` → `1`；注释更新为根因说明。单 runner 内全量文件在同一 worker 顺序执行，antd/recharts 仅加载一次（~2GB），远低于 `max-old-space-size=4096` 上限；并行度靠 3 个 matrix runner 保留（墙钟不退化）。
