- **沙箱 git 教训（重要）**：本会话误用 Python 直接改写 `.git/packed-refs` 去修"本地 tracking 显示陈旧"的小问题，触发沙箱 container 内的 git 视图损坏（坏引用名 `refs/heads/main?`/`refs/remotes/origin/main?` 含 Windows 非法字符 `?`，`git fetch` 报 `bad object`）。结论：
  1. **绝对不要直接改 `.git` 内部文件**（packed-refs/refs/HEAD），交给 git 命令本身；想修 tracking 用 `git fetch`/`update-ref`，且 `update-ref -d` 对含 `?` 的非法名会失败。
  2. 沙箱里 git 子进程与 Python 看到的是**不同的 `.git` 视图**（overlay）——Python 看到的宿主机 `.git` 是干净的，git 子进程跑在另一份被污染的 overlay 上。
  3. **远程是否同步以 `git ls-remote origin <branch>` 为准**，不要信 `git status -sb` 的 ahead/behind（沙箱 tracking 会假陈旧/假 gone）。
  4. 本次宿主机真实仓库最终核验干净（packed-refs 两引用均 → `3a04dba`，commit 对象 loose 存在），远程也确认收到，推送结论牢靠。
