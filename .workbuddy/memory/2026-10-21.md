## 定时任务 worker 环境真 bug 修复（tasks/scheduled_tasks.py）
- **根因**：celery_app.py 无 ContextTask 基座 → celery worker 无 Flask app_context；beat 调度（config.py CELERY_BEAT_SCHEDULE）6 个任务中 4 个在生产 worker 下崩溃/静默失败：
  - daily_summary（每日）：无上下文 + 调不存在的 cache.set_stats → 恒败；
  - health_check（每小时）：无上下文（db.session.execute 恒抛 → DB 恒 unhealthy）+ set_stats AttributeError 逃逸 → 崩溃；
  - warmup_cache_task（每 30 分钟）：warmup_cache() 漏传 app 参数 → TypeError 静默失败；
  - archive_operation_logs（被调时）：无上下文 → except 内 db.session.rollback() 再抛 RuntimeError 逃逸。
- **掩盖模式**：既有 test_scheduled_tasks_archive.py 用 `with app.app_context():` 包裹调用任务 → 测试绿、生产崩。
- **修复**（单文件 + 新测试，未 commit）：
  - 新增模块级 `_resolve_flask_app()`：有环境上下文时沿用 current_app（测试/同步链，防连真实库），否则取 app 单例（worker 路径）；4 个任务统一 `with _resolve_flask_app().app_context():` 自包；
  - set_stats（RedisCache 无此方法）→ cache.set()：daily_summary key 保持 `daily:{date}` 7 天过期；health_check key 不变 1 小时过期；
  - warmup_cache_task 补 app 参数；
  - health_check MQTT 检查导入修正为 services.mqtt_manager.mqtt_manager（原 `from app import mqtt_manager` 恒 ImportError → 恒 unknown）；
  - archive 内层 try 保证 rollback 发生在上下文内再上抛（except 分支不再二次抛错）。
- **daily_summary 条件聚合**（用户确认执行）：func.count + func.sum(case(...)) + func.count(distinct coalesce(student_id,0)) 单条 SQL，替代 .all() 全量取行；coalesce 使 NULL 学号计 1 个活跃成员，与旧 Python 集合语义严格一致。
- **新回归守卫** tests/test_scheduled_tasks_worker_ctx.py（6 例，LF）：无外层 app_context 直调任务模拟 worker；worker_app 夹具经 sys.modules 桩/属性重定向把 app 单例换成测试 app；缓存单例 client 置空 + set 打桩，验证 key/TTL 契约且不写真实 Redis。数值等价断言覆盖 score_change=0 与 student_id=NULL 边界。
- **回归门**：**全量回归 2403/0/0/7 全绿收官**（基线 2397 + 6 新例；22/22 批次 rc=0，hung=0，无陈旧 XML；8 个定时任务用例在 XML 中逐一确认 PASS，含 2 个既有归档用例零改动通过）。ruff/py_compile/EOL 三指标全过。**改动未 commit，待用户显式授权**。
